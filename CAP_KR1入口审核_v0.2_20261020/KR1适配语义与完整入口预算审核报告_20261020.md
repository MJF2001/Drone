# KR1适配语义与完整入口预算审核

日期：2026-10-20。

## 1. 结论先行

**技术门槛通过，原论文等价性不通过。**KR1可称“CAP已知地图重启适配变体”，不能直接改名原版CAP、替换原冻结CAP或据此宣布原论文机制已完整复现。没有开展性能排名，没有使用留出或推送GitHub。

成功批次v0.2：28次入口门槛检查、20份开发道路，均达到各自预设要求。20道路真实路线、采集/历史/遮挡账本和逐决策审核全部通过，外层入口与独立调用计时均小于20秒；新旧求解输出除seconds外逐字段一致。不是根据路线长短修改目标规则。

## 2. 语义审查：哪里有文献依据，哪里是我们增加的

依据：[CAP原文III-C/III-D与Algorithm 1](https://arxiv.org/html/2503.00647v1#S3.SS4)，本项目保存原文文本与当前候选源码。

| 审查项 | 结论 |
|---|---|
| 地区图、最短无碰连接、全局顺序 | 保留既有机制，未以MST等其他方法替换 |
| 全公开时的全局末地区 | 原文允许不指定；与地区内固定终点是两回事 |
| 已知地区局部起止点 | 原文以当前位置为起点、目标格为固定终点，KR1保留该目标形式 |
| NN与2-opt | 保留原语，未增加多候选覆盖路线择优 |
| 第一连接合入巡游 | 不与上述固定起点目标直接冲突；但不是原生独立入区控制器的等价验证 |
| 每次换区按全局L/U/D/R选点 | **新增适配政策**：原文方向贪心属于探索分支，不能直接证明已知分支每区应重用它 |
| 没有邻格时选全局最近待检点 | **新增确定性保底选点**，不是文献唯一给定的重启规则 |
| 已知采集后的批量分裂 | 明确的场景更新约定，不是作者代码逐步等价证明 |

因此，先前的“目标状态可执行、固定终点不被静默重置”是工程正确性证据，不自动证明KR1目标**选择政策**就是论文机制。没有原生历史tau的共同快照，不能伪造已恢复作者状态；也无需为我们的已知地图任务补未知探索。

本轮不继续试多个选点方案挑路线最短者。若使用KR1对照，必须独立标注其名称和以上政策，所有优劣只归当前适配实现。

## 3. 本轮预算入口做了什么

`entry.py`使用字节不变的候选求解器，仅提供外层输入/计时/准入协议：

1. 预加载模块后开始计时，读取调用者提供的JSON字符串/字节。
2. JSON解码、整数格坐标、账本、恢复目标、有限非负资源等验证纳入入口时间。
3. 扣除已用时间，将剩余预算交给原求解器。
4. 将完整求解结果编码为UTF-8 JSON字节，再检查入口耗时是否严格小于预算。
5. 只有外层及时且原结果完整时`eligible=true`，否则`accepted_route=[]`。原始完整/部分路线、诊断与状态保留，不覆盖原始证据。

**eligible只表示此入口的技术准入，不是文献身份/正式排名资格。**原求解结果中的`benchmark_eligible=false`未改，本轮未注册为正式冻结方法。

计时不包括模块导入/进程启动、独立审计、磁盘写入及外层观察记录再次编码。道路另保存调用者从invoke前至其返回后的独立墙钟时间，包含外层返回记录构造开销。若未来共同基准采用冷启动，必须另加共同协议，不能混用。

这是**软截止与超时拒收**，不是强实时抢占。JSON解析/编码或单次内部操作可能跨越截止，不能宣称任何输入都能准点停止；跨过截止的完整原结果不得当及时成功。未新增无限输入规模/深嵌套防护等无关系统，也不宣称已穷尽所有非法输入类型。

## 4. 门槛检查结果

预先封存协议后，执行28次入口调用：

| 门槛 | 次数 | 结果 |
|---|---:|---|
| 固定非法请求（格式、类型、整数/布尔格、账本、恢复目标等） | 19 | 全部求解前拒绝 |
| 0和负时间预算 | 2 | 全部求解前拒绝 |
| entry_begin、after_parse过期 | 2 | 不启动求解 |
| after_solve、after_serialize过期 | 2 | 原求解完成但外层拒收，原结果保留 |
| 一次实际移动后求解截止 | 1 | 真实一步前缀保留，不输出可接受完整路线 |
| 资源为0 | 1 | 资源不足，不输出可接受完整路线 |
| 正常入口 | 1 | 完整且入口准入成功 |

外层及求解截止使用确定性假时钟注入，**不是观察到5个实际自然超时**。这些测试验证准入分支与前缀，不用于计算算法真实性能。

其中只有5次真正调用候选求解器，其余在输入拒绝或入口已过期时停止。异常分类也分开：求解前非法输入是invalid_input；进入求解器后非预期参数/内部错误不得静默包装成正常输入拒绝。

## 5. 新20道路入口审核

使用上一候选相同20份开发输入各一次，20秒暖进程入口预算；不是新的独立地图，也不是两种子排名实验。

- 20/20路线完整、合法且已返航，20/20外层准入成功。
- 最大入口时间：**4.776962秒**。
- 最大调用者独立时间：**4.777465秒**。

- 所有原输入哈希一致；所有求解字段（除seconds）与上一候选保存结果一致。因此本轮不是又改了一种选点算法。

未输出与PPCPP的输赢、平均路程差或优越性结论。时间是本轮这台机器的开发数据记录，不外推其他电脑或大规模性能。

成功批次合计48次入口调用，实际候选求解25次（5个门槛+20道路）。不与上轮115次或失败批次相加宣称更多独立测试地图。

## 6. 初版失败及修正边界

v0.1完成28门槛后，首个道路合法及时返回，却在新旧结果一致性断言中失败。原因是运行器将内存tuple与旧JSON list直接比较；将新结果正常JSON化后无任何非时间字段差异。

v0.1实际29入口调用、6次候选求解，只有1个道路，保留checks.log、gates.json、roads.json、STOPPED.json。它不是成功批次，不混入v0.2汇总。

另建v0.2只修运行器JSON规范化比较；入口和全部候选运行源码与v0.1逐字节相同。v0.2重新封协议、重新执行全部28门槛和20道路，不拼接初版结果。

## 7. 冻结与下一步

本轮**不直接冻结为原论文CAP替代版**，因为预算通过不能解决语义来源问题。

建议将后续研究对象分开：

- 原CAP适配旧结果：保留真实数值及已知接口限制，不再拿其差距直接判断论文机制。
- CAP-KR1：有明确重启/接续规则的已知地图适配变体；若纳入下一轮，应单独命名、固定入口协议与源码，而不是冒名覆盖CAP。

下一步的实质决策是是否接受**CAP-KR1独立适配变体**进入开发对照，而不是继续增加微型测试来替代文献语义判断。若接受，才以独立方法ID固定协议后与PPCPP同条件重跑；如果要求严格作者原版身份，则现有证据仍不足，不能靠宣称测试通过来补足。
