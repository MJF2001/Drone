# CAP完整接续候选KR1：实现、验收和结论边界

日期：2026-10-20。

**已从两个局部组件推进到能完成剩余覆盖并返航的完整场景候选。115次候选求解的实际路线/前缀均通过独立审核，其中包含23次预设截止、资源不足与不可达拒绝；不是115条完整路线。没有开展算法性能排名，也没有冻结为文献忠实CAP。**

## 1. 本轮目的与实际改动

解决原适配每区重新从本区待检格选终点、缺乏目标接续，以及附带采集后残余节点未分裂的问题。保留地区内固定起点/终点，不取消终点约束，不补未知地图探索，不引入统一全局补全。

新建独立候选`runtime/candidate.py`，使用前轮字节不变的`known_sync.py`、原`structures.py`和`primitives.py`。原CAP、其他算法及原280份成绩不改。不是将旧路线配上新分区冒充重跑。

## 2. 缺目标时采用什么规则

输入没有CAP原生目标历史，因此不能声称恢复了原目标。本轮预先写下KR1场景适配规则，见`规则与预登记.md`，再封协议执行测试：

| 决策 | 明确的候选约定 |
|---|---|
| 显式恢复目标 | 有`cap_resume_target`时验证可飞点及来源，允许区外或已覆盖格 |
| 没有恢复目标 | 对全部真实pending按L/U/D/R选邻格；无邻格则选四邻接最短路最近格，等距按坐标 |
| 地区选择 | 仍取原CAP地区图顺序首项，与选目标的集合分开 |
| 地区内巡游 | 当前点固定起点，已绑定tau固定终点，覆盖所选地区所有R |
| 入区 | 第一条连接与局部巡游合并，沿完整公开可飞F执行；不是另做端点优化 |
| 目标生命周期 | 第一连接及途中提前经过tau不改绑；整个巡游到tau结束后标reached，再同步分区，下一地区才显式选择下一tau |
| 分裂影响 | 目标绑定可飞坐标，不绑定地区ID；拆节点不换目标 |
| 剩余全部完成 | 从实际位置四邻接返航；遮挡任务留deferred |

**KR1是明确声明的适配选择，不是经作者代码证实的唯一重启规则。**全局邻格/最近点并不等于在多个端点上解覆盖路线再择优。没有根据测试路程挑策略或调规则。

上一轮局部Session要求调用者先给显式入区路径；本轮候选将首连接合入巡游，没有声称逐字节集成该Session，也没有声称原论文单独的入区控制器已得到验证。复用的是目标不静默重置、固定接口与真实采集责任分离的契约。当前仍须审评这一合并连接解释是否适合作为文献比较的正式约定。

## 3. 预登记与运行顺序

1. 固定规则、代码和20份既有开发输入哈希，保存在`protocol.json`；不是新生成或挑选输入。
2. 执行64个3×2地图目标子集（包含无任务）、5个专项（外部恢复接口、资源不足、遮挡暂缓、已有覆盖、不可达），以及1次截止检查点发现。
3. 对该预定多地区流程观察到的23种检查点，各注入一次确定性截止，共93次微型/截止调用。所有输出前缀审核通过；截止发现不等于穷尽全部分支、全部重复次数的截止验证。
4. 门槛通过后，20份开发道路各执行一次，内部预算20秒，全部完整、合法、返航。这里只做候选正确性验收，没有两种子/多算法共同轮转，也没有胜负或路程差排名。
5. 新道路路线中未发生分裂，故不能拿道路通过证明分裂后接续。另封`integration_protocol.json`，不改候选代码或KR1规则，补两个固定夹具，再执行2次完整求解。

合计：93+20+2=**115次完整候选入口调用**。其中完整完成90次，预期截止23次、资源不足1次、不可达1次。这里“完整候选入口”指调用集成求解器，不表示所有调用都输出完整路线。

## 4. 道路与新增集成夹具的证据

20道路共有30个地区巡游，3个巡游终点在该地区required之外，证明实现没有继续强制“本区待检格才能当终点”。最大内部自报耗时约4.8693秒；**未保存外层完整入口/序列化计时，不能把这个数作为正式共同预算审核结论。**本轮不对路线长度作优劣结论。

道路新路线分裂批次0，与前轮沿旧CAP路线回放出的case10分裂并不冲突：算法路线已变，实际附带采集的时间顺序也变了。不能据此撤销旧缺陷，也不能断言新道路已经覆盖所有更新分支。

新增桥接夹具：公开可飞矩形x=0..2、y=-1..3；待检为(0,0)、(1,0)、(2,0)、(1,2)，当前位置/基地(1,3)，显式固定接口(1,-1)。第一地区覆盖(1,2)后向接口移动，实际采集桥格(1,0)，使另一区分成两个单格分量。结果记录一次批量拆分，随后继续规划剩余地区并返航。目标未在途中被换掉；这是合成机制证据，不是新增独立道路正例。

另一夹具验证无剩余任务但当前位置不在基地时仍返航2步，不能仅因pending为空便宣布返航已完成。

## 5. 独立审核与保存文件

`audit.py`不导入规划器，独立检查四邻接/禁飞/实际采集/历史与deferred账本/资源前缀/返回基地；用独立BFS核对每次KR1选点；核对目标绑定代次、未完成目标不可覆写、巡游固定终点、所需任务、实际路程与局部成本。

`partition_audit.py`独立检查实际运动后的分量、无遗漏/重叠及节点顺序。`verify.py`再将每个局部计划的目标状态与绑定事件逐项对应，并核对原输入、复制源码、协议哈希。核验不求解路线。

- `micro.json`：93次微型/截止输入与输出；`roads.json`：20份新道路路线与审核；
- `integration.json`：2份集成夹具；对应日志/协议均保留；
- `manifest.json`：全部交付文件哈希。
