# KR1完整接续候选：规则先于测试

本目录不是冻结CAP，不覆盖原实现，不使用留出，不排名。原文目标状态缺失的部分不能从历史快照真实恢复，以下明确作为**场景适配候选KR1**，不是作者唯一机制。

1. 保留四邻接、真实落格采集、原CAP地区图/中心及NN和2-opt；只接入已验收的残余同步组件。
2. 初始若明确提供`cap_resume_target={point, reference}`，使用该可飞格，允许已覆盖或区外点；不伪称公共旧路线就是CAP历史目标。未提供则启用预定KR1规则。
3. KR1在**全局真实pending**中按L/U/D/R找相邻点；没有则选当前四邻接最短路最近点，等距按坐标。不是仅在已选地区中挑选目标，也不对多个端点计算覆盖路线后择优。
4. 所选地区由原CAP图顺序决定。一次绑定tau后，局部目标固定为当前位置起点、该tau终点，必覆盖所选地区R；tau可以在其他地区。第一条实际连接同时承担进入地区的功能，不另加一个最短入口优化层。此处是**合并连接的适配**，不同于上一轮组件仅接收显式入区路径的调用边界，不称已验证作者独立入区控制器。
5. 第一连接、途中提前经过/采集tau、其他附带采集均不改变绑定。到整个局部巡游结束才标为reached。之后同步所有残余分裂，下一地区开始才从新当前位置和真实pending按同一规则显式绑定下一tau。
6. tau绑定的是可飞坐标，不是地区ID；地区节点分裂不能悄悄改tau。无未来地图、无执行中事件注入；若未来接口要处理目标格新变障碍，需另建显式失效协议，不属于此快照求解器。
7. 全部有效目标完成后，按同一四邻接模型返回基地；遮挡待检保留deferred。资源耗尽/截止/不可达只保留实际执行前缀，不输出完整route，不额外全局补全。

验收顺序：先封源码/20开发输入哈希；64个3×2目标子集、5个专项、1个截止发现及全部已观察阶段的确定性截止注入；逐决策独立审核通过后才执行20份开发道路各一次、每次20秒的完整正确性验收。截止发现不是普遍截止证明，开发道路不是留出或性能排名。不因结果长短修改KR1规则。

通过也只表示候选工程机制与场景约定可运行，不能自动冻结为文献忠实基线；还须评价KR1选点/合并入区是否适合原文已知分支的解释。若失败保留目录并另建版本，不覆盖证据。
