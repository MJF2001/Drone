## 3. 已落地的显式状态契约

`Session`是**单地区接续组件**，不是完整CAP求解入口，不能直接替换七算法工作器。

| 阶段/条件 | 已实现行为 |
|---|---|
| 没有`τ_target` | 返回`missing_resume_target`，不选最近/最远点，也不默认基地 |
| 绑定目标 | 必须有明确来源和引用；目标须属于当前可飞F，不强制属于本区R |
| 已覆盖的目标 | 可作为固定接口保留，不凭目标状态把其他任务记完成 |
| 目标尚活跃 | 拒绝静默改成另一个目标 |
| 入区 | 只执行调用者明确给出的合法路径，目标来源、坐标和代次不变；不自选入口 |
| 入区途中经过目标 | 如实采集，但不据此丢掉既定接口；是否解除接口由显式阶段决定 |
| 本区尚未接入 | 返回`entry_contract_required`，不悄悄重用旧“入区并入TSP”约定 |
| 所选区残余已断开 | 返回`partition_update_required`并列出分量，不直接伪装成单个连通子区求解 |
| 已知地区局部规划 | 使用原NN/2-opt及最短连接，固定所绑定终点；实际经过的其他任务才记采集 |
| 完成局部覆盖 | 到达原固定接口，标记`reached`，返回`region_complete_transition_required` |
| 再处理下一地区 | 必须显式提供下一目标转移及来源，不自动按新地区重新初始化 |
| 超时/资源不足 | 保存真实前缀、真实待检集合及未完成接口，不输出全局成功 |

所有原型输出均固定`global_complete=False`、`benchmark_eligible=False`，没有全局`route`字段；即使局部执行顺便覆盖了全部目标，也不冒充已经完成返航或完整任务。

**这些是为防止隐式猜测而建立的工程契约。**“先由调用者明确入区，再规划局部”的阶段分离也是本原型的声明边界，并未被包装成原文唯一入口规则；跨区目标转移仍由调用者明确提供，不能说已经复现原生控制器。

### 一个重要机制例

在一条0到5的可飞直线上，目标区为2、3，调用者事先绑定接口1。实际入区执行0→1→2时已经经过并采集1，但目标绑定不丢失。本区只剩3时，局部固定终点仍是1；覆盖3后回到1，再等待明确的下一目标转移。这证明**“已采集”不等于“接口已无责任”**，不能在入区过程中重新把本区最近待检格当作出口。

该例使用调用者声明的合成状态，不声称它是某次原论文运行的真实隐状态，不用它作路线质量排名。

## 5. 精确回放：目标缺失与残余断开的来源

### 5.1 不是我们手上有真实目标却没有传入

原共同条件40个CAP工作项对应20份独立状态输入，**全部没有`tau_target`、`resume_target`或`cap_state`字段**。共同旧路线、当前位置/方向不是CAP原生隐状态，不能直接冒充目标状态。当前不能宣称已恢复作者原目标。

### 5.2 已定位到具体一次实际采集

`medium_g4`控制状态（case10），两个种子相同：

- 开始时，后续将处理的节点0有142格残余、1个连通分量；当时先选节点1。
- 原始路线第3步实际到达 **(23,1)**，该格属于节点0。沿途3格的附带采集使其残余成为139格。
- 删除(23,1)后，节点0分成**2格和137格**两个四连通分量。
- 到第2段规划时仍把139格作为单个节点，现版`sync`没有调用分裂替换。

这证明切断是**已知地图里的实际覆盖造成**，不是新发现未知障碍，修查它不需要补未知探索。它是1个状态的两种子重复，不是2个独立地图反例。

本轮只重放集合和原路径，不重排节点、不重新求解路线。若后续修完整流程，至少必须明确“附带采集影响其他节点后，何时同步分裂、如何更新顺序和目标接口”。原文主要展示探索节点分裂；对本项目快照的更新约定仍须声明，不能先假定唯一排序规则。单地区原型只能阻止在其入口检查时把断开的残余继续当连通区，**没有实现全局多节点同步修复**。
