## A. ε* 截止漏口与截止元数据

**结论**：已修。截止检查覆盖预处理/构造/连接/返航/**返回前审核**；迟到的路线不进入评分；
`meta.deadline` 为最终值。

**实现位置**：`src_v03/adapters/epsilon_star.py::_finish()`

**反例与实测**（`tests_v03/test_a_deadline_edges.py`，全部用手动时钟，不依赖机器速度）：

| 边界 | 做法 | 期望 | 实测 |
|---|---|---|---|
| **连接器跨截止** | 让 `GridMetric.path` 返回后把时钟推进 2 s，预算 1 s | 不得成功；元数据须反映 | `deadline_before_complete_route`、`route=()`、`natural=False`、`soft_deadline_hit=True`、`elapsed ≥ 2.0`、`candidate.accepted=False` |
| **审核跨截止** | 让 `audit_route` 返回后把时钟推进 2 s | 迟到的完整路线只作诊断 | `deadline_before_complete_route`、`route=()`、`candidate.post_deadline=True`、`diagnostic_route` 存在且 `diagnostic_route_steps` 非空、`errors` 含 `post_deadline_candidate_excluded` |
| **截止前已有合法候选** | 不推进时钟 | 正常成功 | `finished`、审计合法、`natural=True`、`candidate.accepted=True`、`post_deadline=False`、`soft_deadline_hit=False` |
| **元数据不是初始快照** | 正常运行后比对 | `checks` 随实际检查增长、`elapsed` 等于最终时钟值 | `checks > 1`；`clock.calls > checks`；`elapsed == clock.value`（9 位小数） |
| **真实时钟纳秒上限** | 5×5、`1e-9` | 立即截断 | `deadline_before_complete_route`、`route=()`、`natural=False` |

复现：

```powershell
Set-Location "$V3\tests_v03"
& $py -B -X utf8 -m unittest test_a_deadline_edges -v
```

术语说明（写入 `meta`）：

- `candidate.generated_seconds`：完整候选产生时刻；
- `candidate.validated_seconds`：独立审计完成时刻；
- `candidate.accepted`：是否被接受为评分结果；
- `candidate.post_deadline`：是否在截止后才通过审核；
- `meta.diagnostic_route` / `diagnostic_route_source`：迟到路线的原文与来源说明，**不计入评分**。

## B. 返回前审核计入本次调用成本

**结论**：已修。`finalize()`（含独立审计）在 `clock.stop_total()` 之前执行；
六个方法现在同一入口/出口边界。

**证据**：`tests_v03/test_b_timing_boundary.py`

**做法**（即复核建议的诊断）：在 `audit_independent.audit_route` 入口注入 50 ms 延迟，
不改变算法与路线，然后要求每个方法的 `adapter_call` 相应增长。

| 断言 | 实测 |
|---|---|
| 每种方法在注入 50 ms 后 `adapter_call ≥ 0.04 s` | 6/6 通过 |
| 与未注入的基线相比，增长 ≥ 0.04 s | 6/6 通过（每个方法先预热一次以剔除首次导入开销） |
| 没有任何方法发布 0 总时间 | 6/6 通过 |
| 内部不重叠阶段之和不大于总时间 | 6/6 通过 |

复现：

```powershell
Set-Location "$V3\tests_v03"
& $py -B -X utf8 -m unittest test_b_timing_boundary -v
```

口径声明（写入 `变更表.md` 与本文件）：
`adapter_call` = 公共入口到"返回前合法检查完成"的墙钟；**外部事后独立复核另计**。
v0.1 的 `run_micro` 外部 `seconds` 另有记录，不因本次修订作废。

## C. 调用记录与账本完整性

### C1 测试/开发不得绕过登记入口

- `registry.run(method, request, clock=None, **adapter_kwargs)`：假时钟通过关键字参数注入，
  不再直连 `epsilon_star.run`；
- `ADAPTERS_WITH_OPTIONS = ("EPSILON_STAR",)`，其它方法收到选项直接 `TypeError`；
- **静态守卫**：`test_no_test_calls_the_adapter_directly` 扫描 `tests_v03/*.py`，
  出现 `epsilon_star.run(`、`cstar.run(`、`reference_methods.run_reference(` 即失败；
- 子进程测试也不直连：它导入 `bootstrap_v03` 后用 `registry._append` 写 start 行
  （模拟被看门狗终止的调用），账本路径指向 `scratch/orphan_ledger.csv`，
  不污染交付账本。

### C2 写失败必须上报，不能吞掉

| 场景 | 做法 | 实测 |
|---|---|---|
| `start` 写失败 | 让 `_append` 抛 `OSError` | 抛 `LedgerWriteError`；**适配器一次都没被调用**；`LEDGER_FAILURES` 记 `phase=start` |
| `end` 写失败 | 第 1 次成功、第 2 次抛 `OSError` | 仍返回规划结果；`result.meta["ledger_write_error"]` 存在；`LEDGER_FAILURES` 记 `phase=end` |
| 批次封锁 | 运行器检查 `LEDGER_FAILURES` | 非空时**不写 seal**，打印 `BATCH NOT SEALED`，退出码非 0 |

失败探针写的是 `scratch/probe_ledger.csv`，用完删除，**交付账本保持 start/end 配对**。

### C3 封存账本前缀

`manifests_v03/ledger_seal.json` 记录封存时的 `bytes`、`lines`、`sha256_of_prefix`。
`verify_v03.prefix_ok()` 只比较前 `bytes` 个字节：

- 追加 → 前缀不变 → 通过；
- 改写旧行 → 前缀哈希不匹配 → 失败；
- 文件缩短 → 失败。

实测（封存批次 `v03_formal_20261018_062201`）：

```
bytes=59119  lines=205  sha256_of_prefix=9026d2bb45d167cdeb77b4b0253c6f4f22befc7d0946bcc1f2177026c2959454
```

（`manifests_v03/ledger_seal.json` 是唯一权威来源；本文件抄录的数字若与它不一致，以它为准。）

测试跑完之后账本行数增加（测试调用也登记），前缀校验仍通过。

### C4 按 run_id 联结正式账本 / 任务清单 / 保存路线

`verify_v03.check_ledger()` 检查：

1. 每个 `run_id` 恰好一行 `start` + 一行 `end`（缺 end → "硬终止/孤儿"；缺 start → 失败）；
2. 没有 `kind='unregistered'` 的行；
3. 正式批次的 `plan_id` 集合与 `run_manifest_v03.json` 的计划集合完全一致（缺/多都报）；
4. 同批次内不得重复登记同一格；
5. 每行 `task_set_sha256` 与清单一致；
6. **联结**：每条 formal `end` 行必须按 `run_id` 找到保存路线，且 `case_id`、`method_id`、
   `status`、`route_steps`、`seed` 逐项相同。

负例（`check_self_tests` + `test_c_ledger_integrity.py` 的 `LedgerAuditNegative`）：

| 负例 | 期望 |
|---|---|
| 删除 `end` 行 | 报告 `start without end` |
| 删除 `start` 行 | 报告 `end without start` |
| 重复 `run_id` | 报告 `run_id repeated` |
| `kind='unregistered'` | 报告 unregistered |
| 保存路线缺失 | 报告 `no saved route` |
| 路线 `status` / `route_steps` 被改 | 报告字段不一致 |
| 账本前缀被改写 | `prefix_ok` 返回 False |
| 进程被杀死（start 无 end） | 报告 `start without end` |

复现：

```powershell
Set-Location "$V3\tests_v03"
& $py -B -X utf8 -m unittest test_c_ledger_integrity -v
& $py -B -X utf8 "$V3\verify_v03.py"
```

## 关于"调用数"的口径（避免再次误读）

- 本次交付账本里的数字是**规划器调用次数**，不是测试项数；
- v0.3 的账本从空开始：正式 102 次调用（204 行）+ 测试调用 36 次（72 行）= 138 次调用、276 行 + 表头；
- 测试每跑一次会**再追加** 36 次调用；
- v0.1 / v0.2 时期的未登记调用数**无法恢复**：只能写"未知"，不编造 `run_id`；
  本次主会话复测的额外调用以主会话报告为准。
