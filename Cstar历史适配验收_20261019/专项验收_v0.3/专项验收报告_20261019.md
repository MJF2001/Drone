# C* 孔洞 剪枝与截止专项验收

日期：2026-10-19。版本：独立的专项验收v0.3；前两版原件、失败证据和交付manifest保留。

**结论：三种孔洞结束形式、保存数据中的剪枝服务可达性，以及19个指定阶段的截止边界检查均通过。本轮通过有界专项门槛，可以准备小中大道路正确性协议，但还不能称C*已在我们的全部场景完成复现或正式性能冻结。**

## 一 本轮补齐了什么

### 三种孔洞结束形式

三个人工夹具均从公开地图和覆盖历史正常进入solve，不手工调用cover_holes、不强行指定case，也不跳过最终覆盖与返航审核。

自由格相同：`(-1,0)、(0,0)、(1,0)、(0,-1)`；当前位置和基地均为`(0,0)`。人工已知边界为`x=-2…2、y=-2…1`矩形内的非自由格，根据分支保留一个格为未知。这是声明过的机制夹具，不是给道路地图偷偷加外圈障碍。

|完整夹具|已知边界中的未知格|自然触发的结束形式|结果|
|---|---|---|---|
|hole_goal|`(-2,1)`|case 1，孔洞巡游固定结束于goal|覆盖并返航|
|hole_start|`(-1,-2)`|case 2，孔洞巡游固定返回本次start|覆盖并返航|
|hole_free|无|case 3，孔洞巡游自由结束|覆盖并返航|

审核器根据孔洞巡游前的图、Open状态、巡游点集及公开未知邻接关系，独立重算应选case，并核对实际巡游顺序和路径端点。这里的start/goal是该次孔洞服务的入口和选定目标，不应与最终基地混淆。

### 剪枝前后的任务表示与可达性

每次剪枝保存当前位置、当时pending、保护集合、剪枝前后节点与边。独立审核不调用规划器的needed或path：

1. 从图快照重新计算当前位置所在连通分量。
2. 将“节点上的目标”和“已有竖向lap内部的目标”分别展开，计算被表示的任务及可达任务。
3. 完整剪枝不得丢失剪枝前已表示或可达的任务。
4. 对最终成功的夹具，额外要求每次完整剪枝前后都表示且可达全部当时pending，而不只是两份同样缺任务的集合相等。

主批中共审核203份完整剪枝记录；另有4份截止注入时中断的剪枝记录单列保留，不将中断状态认定为可继续执行的有效图。以上是本轮保存数据的性质，不是任意拓扑的数学证明。

### 截止与中断

独立版本增加协作式检查点：初始采样/扩展、任务通路保护、RCG搜索、剪枝部分循环、BFS与路径重建、移动前后、孔洞加密、TSP成本构建、最近邻、2-opt、返航、最终审核及结果就绪阶段。采用`clock >= deadline`拒绝，解决恰好等于截止点的边界。

对19个指定阶段，各测试“截止前1微秒、恰好截止、超过1微秒”，共57次受控时钟调用。19次截止前调用正常完成；38次恰好/超过截止均拒绝正式路线。所有注入阶段都有实际命中证据，不用“没有走到该分支”冒充通过。返航BFS单独在进入返航后才触发，避免被前面的采集BFS提前截断。

**这不是57次真实耗时实验，也不证明硬实时性能。** Python内存分配、排序、部分集合运算、地图几何判断和其他未细分区间仍不能保证立即抢占；应称协作式截止与结果拒绝验收。

## 二 新发现并修复的中断账本问题

旧v0.2在整段navigate返回后才更新pending。若执行一个RCG边的四邻接展开时中途截止，诊断轨迹已经经过的目标可能还留在pending中。

在未修改的v0.2上，以2×2自由地图的一条对角RCG边进行隔离诊断：执行第一个单位步后、第二步前注入中断。保存轨迹已含`(1,0)`，pending仍含该点，且没有task_events。见legacy_interrupt_probe.json。此诊断只证明旧版的中断记账缺口，不是一次完整覆盖求解，也不混入主批成绩。

v0.3使用finally按实际已追加的轨迹更新账本，并标记事件interrupted；中断后仍不输出可执行完整路线。主批中move_after的恰好截止和超时两例均保存了已走一步的真实前缀，已到达目标从pending中扣除，未到达目标仍保留。不能把诊断前缀当作可继续执行的完整返航方案。

构造阶段新增的截止也由solve入口捕获，不再让初始化超时直接逸出为未分类异常；结果结构构建后还有最终截止拒绝。中断后的半成品图不复用到下一次求解。

## 四 当前可以如何表述C*

建议表述：

> 已实现并通过有界微型及专项验收的C*核心机制场景适配候选版，可利用历史完成进度；原生机制继承、当前模型替换和新增RCG通路规则有明确边界。

不宜表述“完整复现C*、适用于全部道路状态、已证明完备或已优于其他算法”。单格采集替代连续圆形覆盖、全公开地图下采样退化、欧氏图代价与四邻接执行代价不同、重建而非增量复用旧RCG，以及新增通路责任规则，仍然都是适配边界。

机制来源与适配对照另见本目录的机制适配边界表_20261019.md。它核对当前可执行源码与继承关系，不代替原论文逐条忠实性审查。
