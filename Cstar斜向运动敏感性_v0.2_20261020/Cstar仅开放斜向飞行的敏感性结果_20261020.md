# 仅给C*开放斜向飞行：运动模型敏感性结果

日期：2026-10-20。**40次均完整合法及时。本版是用户指定的异构运动自由度诊断，不替换原四邻接七算法排名。**

## 1. 实际改了什么

在C* v0.7的独立副本中，保留RCG及欧氏图权、原A*、孔洞检测、任务域/通路域区分、目标选择、NN/2-opt、固定TSP端点和等价效率实现。只改变运动执行及相应物理审核：

- 水平/垂直移动距离1，单位对角移动距离√2。
- 对角两侧格必须都可飞，禁止穿障碍角、跨未知区或越出F。
- 只对实际到达的格中心记有效采集；对角触及另外两个格的角，不算完成它们。
- RCG边仍按原图执行，长竖边逐格展开；现在相邻对角边直接执行，不再拆成两个四向动作。
- 返航也采用相同8邻接/禁穿角的最短距离；资源约束、结果字段和审核均按**实际加权几何路程**，不是把斜向一步按1收费。
- 当前采集域、地图、历史、当前位置/基地、资源数值及原40状态/种子不变。未给其他算法改动作或重跑。

四个`history_core`文件、等价TSP模块及旧四向连接器共6文件与v0.7逐字节相同；通过适配器覆盖实际运动连接器并增加独立8向几何模块。旧四向连接器留在副本中，但实际执行走新增连接器，不能凭旧注释判断本轮运动。

这是**改变运动模型**，不是对旧输出逐字段等价的修正。其他算法仍输出原四向路线，尽管其几何路程可同样计算，动作集合不相同，不能据此宣布纯算法优胜。

另建本目录v0.2，**只修运行器打印字段**，8份运行源码与首版完全一致。目录/协议为运行器v0.2，原始结果运动实现标签仍是`CSTAR_DIAGONAL_SENSITIVITY_v0.1`，两者在协议中分列，不混版。

本版在运行前封存协议及源码/输入哈希，顺序：

1. 10项测试全部通过：√2代价、单/双角障碍、只记到达格、旁侧任务不虚记、加权资源拒绝、空任务返航、独立距离对照、截止和历史/暂缓账本。距离对照夹具22格，共484个有序端点对。
2. 沿用62个旧微型/孔洞门槛：56完整、6预设负例拒绝，全部符合预期。
3. 26阶段×截止前/恰好/之后=78次合成截止检查通过，另1次阶段发现调用。检查新连接、直达、搜索、重建及原生图/TSP/账本/返航等阶段，不是硬实时证明。
4. 通过后执行原道路20状态×两种子×20秒=40次，35秒进程看门狗，串行，不重试、不提预算、不用留出。

首轮重复的同10项测试不能计为20项不同测试，首条中止批次微型不混入本版62次。

## 4. 收益究竟来自哪里

另做只读分解，完整规划调用0次：

- 40/40的RCG导航序列与四向版相同；
- 40/40的选点原因、孔洞集合和TSP访问顺序相同；
- 每例路程减少都符合`对角动作数×(2−√2)`，合计172×(2−√2)=100.7553。

因此，**本批收益是把原有对角图边从两次四向执行还原为直接斜飞的几何收益，不是重新设计了C*访问策略。**这也表明我们没有通过换掉RCG/TSP、增加优化候选来制造路线变化。

这里只验证规划决策/图路线，不宣称所有瞬时采集集合或返航轨迹逐点相同，也不推广为任何输入下两模型都会保持同样决策。

## 5. 对PPCPP的解释边界

作为用户指定的**混合动作模型观察**，沿用同输入的冻结PPCPP四向结果，不新增PPCPP调用：PPCPP相对C*斜向版平均路程仍少约0.9943%，20次更短、2次同、18次更长。这个平均数不表示PPCPP普遍更优，也不替代原共同四邻接下的−3.00%结论。

可说：给C*恢复直接斜飞后，本批差距有所缩小；单凭图权/执行差别不足以解释全部观察。不可说：异构运动实验已经证明论文算法优劣或完成了原论文场景复现。

原七算法v0.3的280次及原排名、C* v0.7候选冻结均未修改；本版不作为正式共同模型替代品。若以后要统一允许斜向，需要为所有方法另定模型和验收，而不是直接把这40次替换进原280次。
