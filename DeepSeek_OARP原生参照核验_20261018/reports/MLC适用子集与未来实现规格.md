# MLC 适用子集与未来实现规格（本轮只交规格）

来源：作者 2025 年学位论文第 5 章（`sources/literature/MLC_chapter5.txt`，印刷页 70–87）。
期刊最终版（2025 RA-L）**未取得全文**，不能声称两版逐字一致。
`MLC-Maps` 仓库只提供地图；**本轮未确认**可直接运行的作者完整实现（定向查找未找到，
不等于作者一定没开源）。

## 1. 机制概要（据第 5 章）

1. 先求最少条带（与 OARP 相同的 rank 划分）；
2. 把每条带的两个端点做**最小长度完美匹配**，形成若干闭环；
3. 用**双边连接**或**角点交换**把闭环合并为一条路线，合并时允许**拆开条带**；
4. Lazy 版本先用距离下界筛选，只精算匹配选中的边；
5. 第 5 章定理 5.2 给出原条件下 `1.5 + m/n` 的长度界。

与现有 OARP 系列的区别：OARP 优化"少转弯 + 少改变"，MLC 直接优化**路线长度**。

## 2. 原生适用子集（原条件成立的输入）

- 目标集**连通完整**（需要覆盖的就是整块区域），共同基地，**闭环**行程；
- 条带端点同坐标时仍需**区分端点身份**（同一条带的两个端点是两个匹配节点；
  不能因坐标相同就去重，否则匹配语义变了）；
- 匹配输入：端点集合 + 端点间最短长度；输出：完美匹配的边集合；
- 合并输入：若干闭环 + 当前长度；输出：合并后的单环与长度（可能拆开某条带）；
- lazy 输入：距离下界矩阵；输出：与精确版相同的匹配，但只精算部分边。

**哪些是核心**（不能删）：最少条带划分、端点完美匹配、双边/角点合并、长度不增验证。
**哪些是参数/实现选择**：lazy 的筛选阈值、下界形式、匹配求解器、合并顺序。

独立核验方法：给定输入，独立枚举端点匹配与合并顺序（小规模），比较最终长度；
核对合并过程中每条带至多被拆一次、每个端点恰好出现一次。

## 3. 我们场景需要的适配

| 需求 | 需要的适配 | 不能怎么做 |
|---|---|---|
| 四邻接单位步 | 连接代价换成网格最短路；角点交换的重接路径必须逐步校验合法 | 只替换一张距离矩阵就称"已适配" |
| 固定异起终点（当前位置≠基地） | 把两个端点接入闭环（例如把基地与当前位置作为两个必须相连的端点插入） | 直接当闭环用，默认端点重合 |
| 只覆盖 Q ⊂ F | 服务域是 Q，通行域是 F；匹配图按 Q 的条带端点建 | 把整个 F 设为目标来"补全连通性"（会无端增加任务） |
| 旧块冻结约束 | 旧块内部顺序固定会限制拆边/换边；需要明确"允许拆哪些块" | 假设所有合并动作仍可用 |
| Q 不连通而 F 连通 | 需要跨分量的连接代价；合并图可能不连通 | 强行要求 Q 连通，或强制覆盖 F |

纯结构反例（本轮已确认成立，不需要运行 MLC）：F 为 (0,0)…(4,0) 五格、Q 只剩两端、
中间已覆盖但可通行。无人机可经中间完成两端，但只按 Q 的相邻关系建图会得到两个孤点。

## 4. 理论界不能直接继承的条件

- 原界的覆盖域是"连通完整目标"；我们的 Q 可能碎片化、且 D 被排除；
- 原界假设闭环；我们是固定异端点路径；
- 原界基于欧氏几何与某类连接；我们用四邻接单位步；
- 原工作的 LKH3 欧氏 TSP 参照**可能穿障**，不能当本场景的合法最优证书。

因此：本场景不能声称 `1.5 + m/n` 成立；若将来实现，必须重新推导或只作为经验参照。

## 5. 下一轮的最小实现顺序（不预告收益）

1. 在**连通完整目标 + 共同基地闭环**的小图上实现匹配与两类合并，配独立枚举核验；
2. 加 lazy，与精确版结果比对（必须相同）；
3. 处理固定异端点：先用"接入闭环"的构造，报告长度差与合法性；
4. 处理 Q ⊂ F：先只支持 Q 连通的情况，不连通时明确报 `not_applicable`；
5. 最后才考虑旧块冻结约束下的合并限制。

每一步都要有失败/拒绝语义；不允许用"补检整个 F"来伪造完整覆盖。
本轮**没有**实现、试跑或宣称 MLC 优于现有方法，也没有下载或编译新求解器。
