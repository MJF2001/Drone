# OARP_CORE2与原文的适配程度审查

2026-10-18。范围：原文2311.17837v2；本轮开发比较真正调用的冻结v2源码，不以工作区最新同名文件代替实验版本。只读审查，新增规划器调用0。

## 结论

当前实现确实保留了有实质计算内容的两阶段骨架：模型2条带优化、改变规模预算、旧路径块压缩、双方向GTSP连接。不是普通扫描/A*换名。

但它不是完整OARP-Replan，不能声称逐式/数值等价已经全面证明。最准确的定位是“基于OARP-Replan模型2的剩余任务覆盖核心适配，附带工程稳健化与共同保底”。原论文外层在线运行、原生旧计划结构和运动代价已变化，这些足以影响结果。

因此先前建议优先改OARP仅是选型建议。应先补齐下面的等价核验和状态证据，再设计改进，避免把复现修补当创新。

## 1. 当前源码实际怎样工作

事件后状态→准备合法保底→从旧剩余路线恢复旧条带→经验时间表反查改变预算cap→RANK模型2重新划分Q→将连续未改变的旧条带及旧连接压成路径块→新条带和旧路径块交GTSP选择方向与顺序→四邻接最短路展开→独立核验→在核心与共同保底中保留较短合法路线。

“核心计算”不是最终输出的唯一来源，需始终区分RANK_and_TOUR与old_suffix/common_fallback。

## 2. 实质保留的计算

### A. 每格方向与端点优化

ranks.py::_build给每个待检格H/V两个方向变量并要求和为1。端点变量由相邻格方向差约束。端点总和除以2作为条带数。不是手工固定全横/全竖，而是允许不同位置有不同方向。

这是可以检查的数学求解过程：交给SCIP优化，再解码出覆盖每个目标恰一次的直线条带。中间通行可重复；“条带服务恰一次”不等于整条飞行路线不重复。

### B. 模型2端点改变量

当前variant=2。changed = added + extended/2；约束changed<=cap；目标rank_count+changed/(cap+1)。该形式对应原模型2用端点变化上界约束新条带的思路。

added是新出现端点；extended是旧端点消失但仍保持同一覆盖方向的情况。旧DeepSeek规格写成“方向翻转”不准确，应更正。方向翻转与同方向延长不是一回事。

数少优先、相近情况下少改旧结构，不是直接在rank阶段最小化总步数。模型2本身是原文提供的高效变体；选它不属于擅自把模型1简化掉。但不应声称模型2等同模型1的新条带精确计数或有相同最优保证。

### C. LP求解保留，整数回退增加

先用连续变量求LP，检查所得变量是否近整数，不整则显式重解MIP，没有直接四舍五入蒙混。原文实验使用LP松弛；我们的整数回退是稳健化补充，会改变计算时间，不能归为原论文所有场景必然行为。

### D. 未改变旧路径成块保留

tour.py::path_sets对照新旧条带key，把旧路线中连续未变化的条带连同它们之间原有轨迹封成一个块。块内原先顺序和连接保留；GTSP只决定块的顺/逆向及块间顺序。

这是核心思想的实质实现，能减少后续连接问题规模，也会限制路线自由度。不能把它说成普通全局TSP，更不能把“保留旧结构减少重算”当作我们新发现。

### E. GTSP方向与访问顺序

tour.py::gtsp_instance每块给正向/反向两状态，作为同一组；添加当前起点与基地终点，使用终点→起点零成本有向边编码开放路径。decode_tour检查每组恰选一状态、终点约束、禁用边与展开步数一致。

实际用GLNS求解，不是只做最近邻或手写扫描连接。GLNS仍为启发式，解码代价相等不是最优性证书。依赖被记录为GLNS C++包0.1.0，不能据此称逐行复用了原论文作者的完整程序或证明其默认参数与原实现相同。

## 3. 主要替换和损失

| 部分 | 当前做法 | 影响 |
|---|---|---|
| 原有旧条带 | old_services从P2旧路线中尚未服务目标的首次访问位置切直线段 | 重新解释旧计划；方向、段边界、块数会影响后续模型，非免费格式转换 |
| 通行连接代价 | 全部free上的最短四邻接步数，包含块内部步数 | 删除连续运动/朝向/转弯动力学成本，原任务时间收益不能直接转用 |
| 服务任务 | 只划当前Q，已覆盖和非目标free仍通行，受阻目标暂缓 | 符合用户任务；条带被覆盖历史切碎，行为可能不同于原完整自由空间覆盖 |
| 预算来源 | 外部给1/20/120秒，不从到某次障碍遭遇的行驶时间计算 | 已改成事件后快照求解，不能评价原边走边算收益 |
| 预算估计 | 本机合成服务组校准与保守单调表，冻结cap最高32 | 非原文具体估计器/标定数据；20/120秒cap相同部分来自表上限，不证明更大cap无价值 |
| 新目标 | 将新增区域目标放入Q，仍以旧目标/旧条带作参照 | 是我们的扩展，不是原文已验证支持新增任务的证明 |
| 失败保底 | 完整旧尾段/按旧服务顺序合法连接及补入新目标 | 不等于原论文逐障碍遭遇GD流程；保底胜出不可记成OARP核心路线 |
| 初始计划 | 用P2准备并执行的历史 | 原生OARP初始条带优势/依赖未隔离；当前是统一历史条件化比较 |

old_services细节：沿旧路线第一次经过尚未服务目标才计入作业段；改变方向、跳步或经过非待服务点就切段；单格段默认标H。旧路线若遗漏原待服务目标会拒绝。用原生条带计划时也应核对重建段是否等价，不能凭原路线合法就认定恢复了同一语义。

## 4. 没有进入当前实现的整套机制

当前oarp_solve只对给定事件后Q执行一遍rank/tour，没有逐次障碍遭遇循环、机器人继续运动时后台计算、按遭遇点行驶时间选择起算位置、新观测到来中断/重启的完整在线状态机；也没有原运动模型下的行驶+停车等待总任务时间评价。

这是系统层的重要缺失。若我们只研究事件后剩余任务规划，删除可作为明确的场景适配；若声称比较完整在线重规划能力，则不够。

## 5. 认证修复不是原文机制，需单列

ranks.py在解码覆盖/模型目标不一致时，可能走certification_repair，再加入端点支持、相邻切口成对一致等约束重解。代码明示这些不是原论文方程。

不能把此分支说成原文模型错误的证明，也不能声称加入约束后与原模型可行域完全等价已被证明。它是额外实现处理，需用微型穷举/对照核其必要性与影响。

42号历史报告在当时的检查中记录认证修复0次，可引用为该批历史事实，不能外推到最新300项。最新适配器没有把rank结果的attempts、fractional_lp、used_integer_fallback、certification_repair等逐项完整保留在结果meta里，无法仅凭最终rank_status知道本批每次实际走了哪条路径。

这是机制忠实性证据缺口，不等于已发现本批路线非法。原始源码保留，但“运行了同一模型”比“能输出合法路线”需要更多证据。

## 6. 目标改变是最重要的解释边界

当前rank阶段仍在减少条带数并控制改变数量；GTSP阶段才按步数选方向/顺序。单位步数下，少条带不自动意味着最短完整路线。比如两种划分服务同样任务，一种内部少几步却需多次跨障碍连接，总步数可能反而多。

这说明我们保留了原方法的偏好，但换成了新的评价任务。由此可以研究目标适配，但改目标前必须先确保原模型实现确实对应原文，否则无法分清收益来自修正适配还是新方法。

## 7. 当前可下的判断与下一步

可以下：结构与计算方法有实质保留，不是只有皮毛；数学求解内核比普通扫掠拼A*丰富。不能下：完整复现、逐式/数值全面等价、原文理论保证继承、目前快或短代表原论文原始性能。

在设计改进前，建议完成一项有界的忠实性核验：
1. 逐式对应原模型2变量/约束/目标/解码，特别核对认证修复前后可行域；小图用独立穷举核rank数、端点计数、预算与目标，不用整条路线最优性混淆rank子问题最优性。
2. 原生小型条带旧计划→old_services→path_sets做往返核对，包含单格、拐弯、重复访问、部分执行、受阻连接；再单独检查P2历史适配。
3. 小型GTSP用已有精确核对器验证分组、方向、固定端点及展开代价；核GLNS版本/参数/停止语义，不假定原代码等价。
4. 对预算表只确认模型和标定范围，不先做参数扫描。对外层缺失作明确范围声明。
5. 完整保留各求解分支与核心/保底来源；无法恢复的历史分支标未知，不覆盖旧结果，不为补日志重跑全部300项。

先完成这项核验，再决定OARP类方法是否适合作为改进基础。此报告不启动任何新实验，也不是已经冻结的下一轮执行授权。
