# OARP 参照核查、MLC 精读与后续研究判断

日期：2026-10-18。性质：主会话独立核查及研究建议，不是新算法性能报告。

## 1. 先给结论

**保留 OARP 系列为重点候选，但当前 OARP_CORE2 尚不能直接被当成“忠实原版参照”，也不宜立即开始以超过它为目标的优化。**

本轮增加了具体证据，而不只是重复适配边界：

- 在 10 个预定微图、4 个改变上限上，模型2开启现有认证修复的 40 项全部与独立划分穷举一致；关闭修复的 40 项中，39 项一致，1 项产生不能解码为完整覆盖的代数解。该解被现有代码拒绝，没有被作为合法路线接受。
- 4 个构造的历史往返探针说明：逐格路线不能普遍恢复原生条带身份。一个普通横条带例子保持一致；单格 V、部分执行后的 V 单格、连接途中经过未来条带这三种构造均丢失原生身份。这是存在性证据，不能称为真实地图的 75% 失败率。
- 给定服务块的 4 个小型 GTSP，冻结精确 DP 与独立访问顺序/方向全枚举一致，展开路线合法。没有测试 GLNS 搜索质量或其与原作者程序的参数一致性。
- 作者已有专门优化长度的 MLC-Approx 后续工作。因此“把 OARP 从少转弯改成短路线”“用匹配与合并替换连接”“懒计算连接距离”不能未经区分地作为我们的新贡献。

**下一步的实施重点应是建立原生结构参照和可信的同任务适配，再决定是否引入 MLC 作为强候选；不是继续给当前 CORE2 叠加优化。**

## 3. 哪些部分核准到什么程度

原文参照为 [OARP-Replan arXiv v2](https://arxiv.org/html/2311.17837v2)，重点 V-C 的模型2和 VI 的连接编码。当前实验源固定为：

`DeepSeek_底层算法开发比较_20261018/sources/reference_tree/研究方案_剩余覆盖重规划_20261009/算法小型验证_20261010/frozen_baselines/v2_20261012/source/`。

| 部分 | 当前源码与本轮证据 | 判断 |
|---|---|---|
| 横竖方向、端点计数 | `ranks.py::_build`；端点半和计条带；10 微图独立枚举 | 保留实质模型；有限输入已核对，非全规模证明 |
| 模型2改变预算 | `added + extended/2`，其中 extended 是旧端点消失且方向保持；权重 `1/(cap+1)` | 对应原式；其保守性不能被解释成实现错误 |
| LP 与整数回退 | 先 LP，非整数显式 MIP 回退 | 原文采用 LP；MIP 回退是工程补充，必须单列实际触发情况 |
| 认证修复 | 本轮实际触发 1 次，见下一节 | 会改变代数可行域；不能与未加强模型混称完全相同 |

| 双方向与固定端点 | `gtsp_instance`、`decode_tour`；4 个精确子问题核对 | 当前单位步数编码在这些小图成立 |
| GLNS 搜索 | 本轮未调用 | 依赖名称和合法输出不证明与作者版本/配置/质量相同 |
| 原生旧条带 | 入口仍只接逐格路线，再调用 `old_services` | 不能普遍保持身份；尚需新参照接口 |

| 在线外层/运动代价 | 单次四邻接快照，非完整原文机器人在线系统 | 属于明确适配；不评价原系统总作业时间 |

原文两阶段思想、固定端点 GTSP、改变预算都有真实计算保留。但现在能验收的是“有限范围内的子问题与编码核验”，不能改称“原作者整套算法已经严格复现”。

## 4. 认证修复的具体触发例：为什么不能跳过它

旧条带是同一行的 0、1、2 三格；新增第3格，当前目标变为 0、1、2、3；cap=1。

合法地把它扩成一条四格条带，会新增右端点 R3，移除原右端点 R2，同时保持 H 方向。因此当前模型2的改变计数为 `1 + 1/2 = 1.5`，超过1。虽然物理上只形成一个新条带，模型2使用的是保守端点上界；不能把二者混为一谈。

独立穷举确认，在本例 cap=1 时没有满足这个上界的真实条带划分。但未加强模型给出 objective=2 的整数 LP 解，冻结解码器发现目标没有完整覆盖，返回 `invalid_original_model_solution`。开启认证修复后，返回 `infeasible`，与独立穷举一致。

一个解释该现象的代数见证是：全行保持 H，但同时保留 R2、R3 两个右端点、只有 L0 一个左端点。原相邻差分下界未排除此种不成对端点；计数变为1.5条、changed=1，总目标2。解码从 L0 走到 R2 即停止，漏掉第3格。该见证与保存的拒绝目标值相符；本轮日志未保存全部原始 SCIP 变量，故不声称这是求解器返回向量的逐变量重放。

认证约束对任意真实整数条带划分均应成立，例如 `endpoint <= orientation`，以及相邻点 i、j 的 `R_i-L_j=x_i-x_j`：同向合并时两侧皆0，同向保留切口时两侧皆1，换向时为相应正负端点。它们可以排除上述假端点。**这说明存在合理的物理一致性加强理由，不说明加强前后的 LP 可行域相同，也不是“修复就构成创新”。**

边界：这是我们当前实现、当前扩展适配的小例子，不是作者程序的运行结果；新增目标也超出原文主要障碍重规划实验。本轮不能据此判原论文错误，更不能追认历史300项中的触发率。旧适配器未完整保存相关分支，历史缺口仍为未知。

## 5. 旧条带恢复为什么需要改

单格没有可从轨迹推断的几何方向。当前 `old_services` 将它默认记成 H，所以原生 V 单格、或者竖条带执行后剩下的单格，都会丢失原方向。方向虽然不改变这个单格的物理服务，却会改变后续端点比较、改变预算和未变块身份。

另一构造例中，原计划有 A、B、C 三条带，去 B 的连接路线先经过 C 的部分目标。按首次访问切段，会将那些格子重新归入早先的段，得到与原生划分不同的条带。它仍能对目标作不重复划分，但不能证明恢复了原模型状态。

这不是断言“按首次覆盖记账错误”。在我们的移动即覆盖模型中，物理账本必须如实更新。**需要分别保存原生计划结构、实际经过轨迹、实际覆盖账本；三者不是一种数据，不能互相猜测替代。**

拟定接口至少保留：原生条带ID、轴向、规范格序列、计划访问次序/方向、连接轨迹及索引、已经执行的位置、物理覆盖记录。事件前因执行而更新剩余服务，与事件后因障碍而改变条带，分开记录；不得把障碍造成的新段预先标为“原本未变”。

这些探针是手工给定的结构，不是调用原生初始 OARP 规划器生成；真实初始规划→执行→事件的闭环尚未实现，不能把本轮称为原生闭环验收。

## 6. MLC 到底提供了什么参照

发表身份由[作者发表列表](https://www.megnath.com/publications/)与[期刊记录](https://ieeexplore.ieee.org/abstract/document/11146610/)确认：MLC-Approx 的相关论文发表于2025年 RA-L。**期刊最终版全文本轮未取得，机制精读依据作者2025年学位论文第5章（印刷页70–87），不声称两版逐字一致。** [学位论文来源](https://uwspace.uwaterloo.ca/items/e9ac0181-108f-4348-8bd5-cdfaf1277786)

精读摘要：先求最少条带；将端点做最小长度完美匹配形成多个闭环，再合并为一条路线。合并允许拆条带，用双边连接或角点交换减少新增长度。Lazy 版本先用距离下界，只精算匹配选中的边。第5章定理5.2给出原条件下 `1.5+m/n` 的长度界；对照 OARP、TMC、BCD，并设合并消融。其 LKH3 欧氏TSP参照可能穿障，不能当成我们合法路线最优证书。章节结尾已提出与 OARP-Replan 结合的设想。[对应章节](https://uwspace.uwaterloo.ca/bitstreams/262cfb01-e6cf-409b-9e62-fa7317c6f6a4/download)

本地保存了源PDF、分章文本，并查看了算法、定理和图示所在页的渲染。官方可确认的[MLC-Maps仓库](https://github.com/megalphian/MLC-Maps)提供地图；不能把这个地图仓库当成完整算法源码。此次定向查找尚未确认可直接运行的作者完整实现，不等于它一定不存在。

### 6.1 与我们任务的关系：以下是本轮分析，不是原文已有结论

| 问题 | 适配判断 |
|---|---|
| 长度优先 | 与我们步数优先更接近，值得列入强候选；尚无本机性能结论 |
| 四邻接 | 可以考察用四邻接图距离及单位边替换几何连接；需检查合并操作、转角重接路径等全部合法性，不能只替换一张距离矩阵 |
| 原章中的 tour | 算法形成闭合回路；我们常为当前位置≠基地的固定异端点路径。把两点接到回路上能生成候选，不保证公平高质量，也不自动保留理论界 |
| 只覆盖 Q、可通过 F | 剩余目标 Q 可能不连通，但通行 F 连通。直接把 Q 当完整环境，不能保证子回路邻接图连通；把 F 全设为目标又会增加不需要的覆盖任务 |
| 旧块约束 | 固定旧段内部顺序和接回接口会限制拆边/换边；不能假定所有原合并动作仍可用 |
| 理论保证 | 原定理的覆盖域、连通性、闭环结构和长度下界均须逐项核对；不能直接宣称我们的剩余任务也是1.5近似。`m/n` 在碎片目标中也不必很小 |
| 时间收益 | 原工作连接代价昂贵，我们可按格点做BFS并共享同源搜索；lazy是否仍快需要实测，不能搬用原文耗时比例 |

一个纯结构例：F为五格直线，Q只剩两端，中间已覆盖但可通行。无人机可以经中间完成两端；只按Q的相邻关系建立合并图却是两个孤点。该例说明输入语义不能直搬，不是运行MLC得到失败的实验。

另一个手算例：F由 `(0,0),(1,0),(2,0),(1,1)` 组成，当前位置和基地均为 `(0,0)`，Q仅为 `(2,0)`。只完成Q返航可走4步；把F全部强制覆盖则至少6步。因此“用整个F填补Q连通性”可能无端增加任务。

## 7. 经过这轮检查后，改进方向怎样调整

| 提议 | 当前处理 | 理由 |
|---|---|---|
| 修复条带身份、补完分支日志、明确停止状态 | 立即列入参照建设 | 属于正确复现和可信比较，不记作算法创新 |
| 调大cap、改时间估计 | 做有限参照检查 | 原表可能限制搜索；改善不能直接写成新算法优势 |
| 保留旧块、少改一些路线 | 不独立作为新意 | OARP-Replan 已有核心机制 |
| 匹配后合并、允许拆条带、lazy连接 | 作为已有强方法核对 | MLC已覆盖相当部分思想；直接组合也需排除已有设想 |
| 划分与完整路线长度相互反馈 | 保留研究假设 | MLC并不自动排除此方向，但还需相关工作核查和明确失败案例，不能预定新颖 |
| 面向Q⊂F、固定端点与执行历史的服务连接机制 | 优先诊断的候选问题 | 它决定直接迁移的难点；“适配”本身不足，需提出具体新计算方法并验证作用 |
| 在稳定底层上选择释放哪些旧约束 | 保留论文主线 | 与用户范围问题一致；需与原改变预算机制区别，不把地理裁框当研究对象 |

我的建议：**先把 OARP 原生结构参照立住，并为 MLC 明确适用子集；若已有强方法已解决底层问题，就使用它们，把论文贡献集中在有证据的范围释放机制。无需强迫论文同时拥有底层创新和范围创新。**

## 8. 下一步具体实施顺序与停止条件

这是根据本轮证据形成的后续工作清单，尚未执行下面的实现或性能批次。

### A. 建立三个不会混名的参照

1. `OARP_RANK0_FULLTOUR_SCENE`：按当前Q无改变预算地求条带，每个条带独立进入完整GTSP；不把连续旧块固定在内部。用于测“在我们场景下不保留旧结构的条带法”。它仍是启发式路线，不宣称最短全局路线。
2. `OARP_REPLAN2_NATIVE_SCENE`：保存并输入原生条带与实际执行状态，模型2和旧块复用保持原机制；适配四邻接、覆盖账本、基地及资源。用有意义的cap检查区分约束作用与估计器上限，不按结果挑最好参数冒充同预算方法。
3. 当前 `OARP_CORE2`：保留为P2共同历史条件下的已有适配对照，不覆盖旧实验、不改名追认其为原版。

注意：**仅把cap调得很大不等于整体重规划**，因为原来的 `path_sets` 仍可能固定未变块内部顺序。整体对照必须明确解除哪类约束。

### B. 先做原生闭环，再做少量诊断

- 用参照生成初始条带与路线，真实执行固定前缀，独立重建物理覆盖，再公开预定障碍/新增目标；固定单格方向和条带ID，保持账本独立。
- 共同输入比较与各方法自己的原生历史分别报告；不能把不同历史的事件后路线长短直接混成公平配对。
- 分支留存 LP/MIP、认证修复、rank状态/上限、GTSP配置/截止、核心路线和共同保底、构造/距离/搜索/审核计时；成功、核心完成、自然终止分别判定。
- 对照“条带划分是否限制路线”“旧块固定是否限制路线”“连接器搜索是否没找到好路线”，一次只改变一个因素。没有合法核心也照实报告，不只挑能完成的配对。
- 输入、任务数、种子和预算在开跑前另行固定，不凭本轮反例追加性能图；不动留出。

### C. 决定MLC是否进入下一批实现

先在连通完整目标、共同基地闭环的小图核验匹配、两类合并和lazy，再分别处理固定异端点与Q不连通。每个适配都要有失败/拒绝语义；不允许偷偷补检整个F来取得“完整覆盖”。原生条件成立的子集与扩展适配子集分开报告。

若无法在可控成本内保留核心机制，先保留其为适用子集参照，不强行改成一个另起炉灶的算法继续称忠实MLC。

### D. 是否开始新算法开发的门槛

- 参照自身无法稳定正确运行：先修参照，暂停性能创新判断。
- 主要差距来自历史恢复、cap或停止标签：记录为适配/配置问题，不能当新算法收益。
- 出现稳定且可解释的路径冗余，且现有MLC等机制未直接解决：再设计一个针对性机制并消融。
- 强底层已经足够好：冻结底层，回到局部/整体及范围释放研究，不为“必须改OARP”继续消耗轮次。
