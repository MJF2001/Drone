## 1. 多尺度层次

`artifacts/structure_probe.json` + `reports/结构探针_结果.md`。

- 六张图（4×4、8×8、6×4、9×3、5×5、7×5）的新实现 L 与每层块数、块尺寸
  **与按原文规则手算的结果完全一致**；
- 每一层都通过"两两不交 + 覆盖外接矩形"的断言，包括 9×3 长条与 7×5 不等深的情形；
- 没有任何一层包含整图，所以"整图作为粗格"这一旧偏差不再存在；
- 旧实现的每层块数同表并列，可逐一对照（4×4 旧 level1=1 个整图、8×8 旧 level2=1 个整图）。

## 2. 邻居窗口

同一层集合（新实现 Level 1）下比较两种窗口规则：

| 地图 | 块尺寸 | 旧公式块数 | 论文 3×3 块数 |
|---|---|---:|---:|
| 4×4 / 8×8 / 6×4 / 5×5 | 2×2 或 3×2 | 4 | 4 |
| 9×3 长条 | 2×3 | **4** | **3** |
| 7×5 混合 | 3×2 | **6** | **4** |

正方形图上两者一致，**非正方形/长条块上旧公式外扩过头**，这就是不能称"等价实现"的证据。

## 3. 状态机与 Algorithm 1 分支

`artifacts/trace_runs.json`、`artifacts/trace_decisions.csv`、`reports/逐步轨迹_结果.md`。

| 用例 | 臂 | 步数 | 作业数 | 逃逸 | line5 | line6 | 终止 |
|---|---|---:|---:|---:|---:|---:|---|
| t4x4 | old | 18 | 0 | 0 | 0 | 0 | 旧判据 FN |
| t4x4 | transit | 18 | 0 | 0 | 0 | 0 | FN_no_positive_potential |
| t4x4 | task | 18 | 16 | 0 | 0 | 16 | FN_no_positive_potential |
| t6x4_blocked | old / transit / task | 29 | 0 / 0 / 20 | 0 | 0 / 0 / 1 | 0 / 0 / 20 | 均 FN |
| t8x8_obstacle | old / transit / task | 68 / 70 / 70 | 0 / 0 / 62 | 0 | 0 / 0 / 1 | 0 / 0 / 62 | 均 FN |
| t7x7_pocket | old / transit / task | 60 | 0 / 0 / 43 | 0 | 0 | 0 / 0 / 43 | 均 FN |
| t9x9_room | old / transit / task | 82 / 80 / 80 | 0 / 0 / 66 | **1** | 0 | 0 / 0 / 66 | 均 FN |

读法：

1. **旧臂与 transit 臂的 line5/line6 恒为 0**——两条原决策分支从未执行；
2. **task 臂**每覆盖一个目标就作业一次，line5 在含障碍/环形的图上真实触发，
   说明"上下都未覆盖时先移动"这条组织规则回到了控制流里；
3. 20 次运行全部在覆盖完整后由算法自身 FN 终止，没有触发人工 `state_cycle` 或步数上限；
4. `t8x8_obstacle` 上 old=68 而 transit=70：**只修层次/邻域**也会改变路线，
   所以"结构修正"和"覆盖口径修正"是两件不同的事，不能合并归因。

## 4. 死端逃逸选中多大区域的细格

`t9x9_room`（唯一触发逃逸的交付用例）三臂的逃逸决策：

| 臂 | 逃逸层 | 选中格 | 说明 |
|---|---|---:|---|
| old | 1（旧编号＝4 个 5×5 粗格） | (7,0) | 旧的最细粗层不存在，只能从 5×5 级粗格里取 |
| transit | 2（新编号＝4 个 5×5 粗格） | (6,2) | 先试 level 1（小块）无正势，再上到 level 2 |
| task | 2 | (6,2)/(7,1) | 同上，两个种子不同 |

设计探针补充（`logs/design_probe.md`）：8×8 房间型地图上，新实现在 **level 1**
命中 2×2 粗格 `(4,5,0,1)`（4 个候选细格），旧实现在同一张图的 level 1 是 4×4 粗格
（16 个候选细格）。**这就是"随机细目标来自多大区域"的差异，不是编号差异。**

  `test_level_neighbourhood_...`）。

## 6. 统一接口

`artifacts/interface_runs.json`、`reports/接口微跑_结果.md`：4 次调用，
两种模式都返回共享结果行，独立审计 `valid=True`、`coverage_complete=True`、
`natural=True`，且任务模式的作业数与 line6 触发次数一致（16/21），
传输模式为 0。route 步数在两张小图上相同（18/30），说明这个对照
**改的是决策过程而不是长度**，长度差异要在更大的图上才显现。
