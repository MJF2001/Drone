# ε*新版本阶段验收：接受机制修正，暂不冻结性能基线

日期2026-10-18。对象DeepSeek_epsilon忠实性核验_20261018。

## 结论与已做复核

接受为“修正多尺度结构、恢复原决策分支的机制参考实现”。不再以旧ε*结果证明原算法质量差；也不将新版本立即称为当前场景下已完成验收的忠实性能基线。

主会话实际运行verify.py，214项通过；重跑20项单元测试，全部通过。单元测试不执行完整ETM.run，本次新增完整规划器调用0。阅读maps_faithful.py、etm_faithful.py、adapter.py、对应表、限制、接口结果、设计探针和检查器。

阶段认可：粗层不再漏掉最细粗块/加入整图根；控制账本task模式使Algorithm1 L3—L6恢复可达；局部势更新和祖先块更新不再用旧全图重建方式；新增适配/未实现有披露。结构修正并不保证路线一定更短，68→70的例子不是修正失败的证据。

## 1. 转角项：可作为内部决策偏好，不改主评价目标

论文式(5)有距离和转角项，恢复该项有机制依据。我们主目标仍为完整路线步数/计算时间，不评价真实电量。文献基线可以保留其原有转弯偏好，不能因此直接判为不公平；但不能说这使它已经在直接优化单位步数。

当前记录支持的说法：在本实现、所测种子、随机平局、每格反馈及人工state_cycle组合下，CTu=0出现震荡/截断，CTu=1在若干探针上消除该现象。

不支持的说法：CTu在所有实现中不能为0，或1是原论文指定/唯一正确参数。随机过程被不含RNG状态的安全键提前停止，与真正无限不终止不同。应将绝对化措辞改为实验条件下观察。

还须说明量纲：travel_cost=1按每步，turn_cost=1按每度；90度转角贡献90，和90步距离贡献同量。这不是“几乎不影响选择”的开关。在L5两相邻等距候选时任意正权重可打破直行/掉头平局，但L8多候选可能有不同距离，权重会影响实质路径选择。先固定并披露参数/平局/初始朝向，性能前协议可另定有限敏感性；不要现在为求短路扫描参数。

## 2. task模式是原控制参考，不自动等于剩余任务语义完整适配

当前task模式只在WT将控制势场置E；物理覆盖由路线审核重建，engine.move也记录经过的目标。保留控制状态用于组织扫掠本身不构成非法，但二者可能不同步：物理已检格仍可在控制场保持U，后续再访问/逻辑task。

须将控制状态明确命名为控制待处理，而不是实际未采集；task动作若只是控制状态更新，不应虚构额外采集时间，也不能将同格重复覆盖记为新完成。所有额外飞行仍计入路线。

下一阶段记录物理覆盖首次完成时刻、控制FN时刻、返航结束；保留真实历史账本，不为激活L5重置真实已检格。若物理已完成但控制仍扫掠，报告额外路程，不擅自提前终止主版本后仍称原流程。是否引入基于物理完成的早停应另名并单独评估。

原文对应表关于Theorem1/Corollary1的“保留”，应限于保留相应规则/单次逻辑task的约定；20条微图自然结束不是当前四邻接、图距离、历史初始化、重算方式下有限终止定理的证明。

## 3. 生产接口明显回退，性能重跑前必须复用已有可靠封装

src/adapter.py仅按terminal设置finished/planned_at_timeout；即使audit.valid为false，也只是放errors，不将finished降级。没有把request.termination传成Deadline，缺统一输入核验、不可达处理、返回前截止候选接受和公共两阶段账本。

这一轮是机制核验，不要求已经做完整性能工程；但它不能直接替换v0.3封装就跑1/20/120秒。应在独立新版本复用已验收的输入/截止/finalize/登记/独立审核层，只替换核心，保留真实软截止、人工上限、资源超限与失败状态。无需重造整套审计平台。

## 4. 尚需澄清的文档/证据范围

- 四邻接不意味着必须每步重选航点；也可以沿合法路径逐格执行而保持航点。这是控制频率选择，不是运动约束强迫唯一实现。
- 7×5不均匀粗格的延续铺砌、长条地图单轴划分应标为合理扩展/实现解释；覆盖与互斥断言只能证明它是铺砌，不证明这是原文唯一规定。
- “只对Q正势会改变B均值”不准确：外生B均值按块几何定义；改变目标/覆盖主要影响U比例，除非域也改变。
- GridMetric.path有缓存，不是每次调用都重新BFS；确实可能构造多源全图行，耗时需剖析，不能笼统写每次整图BFS。
- verify.py的结构复核复用了当前build_tilings，轨迹分支/覆盖主要核保存摘要；逃逸检查没有重新几何验证chosen属于所报块。接口部分主要信保存的audit字段。它不能独立证明所有轨迹忠实或覆盖合法。
- 清单目录目前仅source_copy.json，未见新代码/产物的完整交付SHA256封存。检查器通过主要支持复制来源未变，不等于新版源码/产物均已封存。
- 设计调用11次有披露，但只有文字探针，不能作为与封存轨迹同级的可重放证据。原始轨迹48行中被取代尝试保留是正确做法，历史不可恢复证据继续标明。

## 下一步建议

先接收机制修正成果，不重跑旧300项。做一次范围有限的集成：更正文档绝对化结论、冻结task模式和参数、复用v0.3公共封装、补物理/控制账本的区别记录、独立重算保存路线与分支、封存新代码。

完成上述性能准入检查后，再预定ε*单方法的有限开发重跑和归因消融。结构、记账口径、转角权重、数据结构更新同时改变，不能仅旧/新两组差异都归为某一项。保持其他方法旧数据，只在信息、任务和时间口径相同条件下比较。

OARP仍为优先考察候选，但不根据ε*旧错误版本决定最终底层。ε*恢复候选资格的方向合理，最终性能要在修正后验证。没有充分理由要求现在推倒重做所有基线。
