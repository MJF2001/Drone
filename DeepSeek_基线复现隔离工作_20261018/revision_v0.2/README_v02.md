# DeepSeek 交付修订 v0.2（2026-10-18）

本目录是对 `../`（v0.1 交付）的**修订**，不是第二次完整交付。
v0.1 的源码、结果、日志与清单**原样保留**，没有原地刷新任何哈希。

## 1. 这一版为什么存在

主会话独立验收（`../主会话验收_DeepSeek_20261018/验收意见与修订要求.md`）的结论是：
"接收为阶段性交付，不通过可冻结进入性能比较的验收"。指出的 7 条问题里，
R1—R3、R5 影响**成功率、耗时与状态语义**，必须先修；R4 是 C* 的定性错误；R6 是证据缺口；
R7 是下一轮协议。

因此本版**只做正确性修订**：不开性能比较、不做参数搜索、不用留出、不改 `../sources/`。

## 3. 怎么跑

```powershell
$OUT = "D:\0A无人机仿真02\问题分析+文献分析\DeepSeek_基线复现隔离工作_20261018"
$R   = "$OUT\revision_v0.2"
$py  = "D:\0A无人机仿真02\问题分析+文献分析\.remote_Drone\运行环境\python\python.exe"
$env:PYTHONDONTWRITEBYTECODE = "1"; $env:PYTHONUTF8 = "1"; $env:PYTHONIOENCODING = "utf-8"
$env:TEMP = "$R\scratch"; $env:TMP = "$R\scratch"

# 1) 只读验收（不启动规划器、不联网、不重建结果）
& $py -B -X utf8 "$R\verify_v02.py"

# 2) 重跑本版测试（只写 logs_v02 的调用账本，不碰 v0.1 的封存件）
Set-Location "$R\tests_v02"
& $py -B -X utf8 -m unittest discover -s "$R\tests_v02" -p "test_*.py" -v

# 3) 生成新一批正式微图结果（会写 artifacts_v02 / logs_v02）
Set-Location "$R"
& $py -B -X utf8 "$R\run_micro_v02.py" --kind formal
```

`verify_v02.py` 做六件事：核对 v0.1 封存件未被改动、核对本版交付哈希、
用独立审计器重算每条保存路线并套用 R5 语义门、校验调用账本（唯一 run_id / 计划集合 /
重复 / 任务集哈希）、运行语义门的负例自检、检查无 `__pycache__` 与残留临时文件。

## 5. 边界（务必一起读）

- **这是正确性修订，不是性能结论**。102 次微图运行只说明"合法、可复现、状态语义一致"；
- **不能判断 P2 是否已经很好**，也不能据此决定改进哪个算法；
- **C* 仍是重启诊断版**：账本不进入核心规划状态，默认不进入下一轮排名；
- **参照集合不完整**：TRACE 与 LKH 尚未接入；
- 逐格路线与 v0.1 相同（102/102），差异集中在**状态、计时与账本**，不是算法行为；
- 本轮仍未提交、未推送，未修改 `.remote_Drone`。

## 6. 已知剩余缺口

1. ε* 的 `state_cycle` 仍是**人为安全截断**（不是原论文终止），已改名与注明，但没有更强的终止策略；
2. C* 的历史适配只给了方案，没有实现（按 R4 要求"不为完成度胡乱加强"）；

4. 05:30 那次完整性级别调整是否起过作用**未知**，且改动前的标签没有采集；
5. 下一轮协议的预算、任务数上限、种子与实例名单仍是 TBD。
