## 2. 代码变更清单

v0.2 采用"覆盖式"目录：`src_v02/` 里只放**改动过**的模块，其余模块由 v0.1 只读复用。
`src_v02/bootstrap_v02.py` 显式设置解析顺序（`src_v02` 在前、`src` 在后，并清掉重复项），
避免"调用方先把 src_v02 放进 sys.path 反而让 v0.1 抢先"的坑。
`bootstrap_v02.resolution_report()` 可打印每个模块的真实来源。

### 2.1 新增

| 文件 | 作用 |
|---|---|
| `src_v02/deadline.py` | 协作式软截止对象（可注入假时钟）；与外部硬看门狗分工写明 |
| `src_v02/finalize.py` | 唯一的"路线 → 结果"出口：合法运动 + 返航 + 完整覆盖 + 资源四项必须同时满足才允许成功状态 |
| `src_v02/bootstrap_v02.py` | 修订版模块解析与隔离断言 |
| `src_v02/adapters/registry.py` | 注册表 + **调用记录器**（每次调用写账本，含 kind/run_id/plan_id） |
| `verify_v02.py` | 只读检查器（含 R5 语义门与负例自检） |
| `run_micro_v02.py` | 正式微图运行入口（每格登记，缺漏/重复可检出） |
| `tools/build_behavior_matrix.py` | 生成 v0.1↔v0.2 逐案例对照 |
| `tools/build_manifest_v02.py` | 生成 v0.2 交付哈希与"相对 v0.1 是否改动" |
| `tests_v02/*`（4 个测试模块 + `conftest_v02.py`） | R1/R2/R3/R5 回归 |
