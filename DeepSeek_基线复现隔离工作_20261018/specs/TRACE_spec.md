## 1. 为什么只做规格

执行稿第 5 项已定：TRACE 与 LKH 本轮只做可行性审查与下一阶段规格。
理由不是它们不重要，而是先要把历史接续、固定端点与终止条件验证清楚，

## 2. 原机制（按精读第 4—7 节）

### 2.1 地图符号状态

四种符号：`U` 未知、`O` 障碍、`Fc` 自由已覆盖、`Fu` 自由未覆盖。
关键规则（精读 §4）：若当前格在本条扫描线上**上下两格仍为 Fu**，则暂缓把当前格标为 `Fc`。
即符号状态带**规划控制用途**，不总是"物理走过一次就立即完成"。

### 2.2 覆盖树（精读 §5）

- 每个节点维护：创建时固定的所属子区域 `A(n)`、当前剩余区域 `R(n)`、剩余区域中心 `p(n)`、状态 `Q(n)`；
- `R(n)` 只保留 `U` 与 `Fu`；节点状态包括完成 `C`、全探索未完成 `E`、仍含未知格的探索中；
- 更新步骤：
  1. 地图更新得到发生状态变化的栅格集合；
  2. 用"栅格→叶节点"索引，只定位受影响叶节点；
  3. 更新这些节点的 `R(n)`、`p(n)`、`Q(n)`；`p(n)` 落在 `R(n)` 外时投影到最近格；
  4. 对非空 `R(n)` 做**四邻接洪泛**，识别连通分量；
  5. 仍是一块不分裂；分成 J 块则建 J 个子节点，父节点变内部节点，更新索引。
- **树边表示分解继承，不表示可行运动连接**；
- 分裂判据用四邻接，而局部目标候选来自 3×3 邻域并检查**直线无碰撞**——两者不是同一种邻接；
- 分裂有两个来源：新发现的障碍，以及已覆盖格退出剩余集合；
- 原文**没有**给出扩容、分支合并、完成区域重新激活的规则（精读 §5 末）。

### 2.3 增量全局访问顺序（精读 §6）

- 活动叶 = 尚未完成的候选区域；已有序列逐项处理：仍活动保留相对顺序，完成则移除，分裂则用子节点序列替换；
- 例：`A→B→C`，`B` 分裂为 `B1,B2,B3`，则以 `A`、`C` 为前后衔接，对 `B` 的子节点做局部 TSP；
- 边权 = 代表中心之间的 **A\*** 最短距离，2-opt 求近似顺序；
- 该 A\* 的通行集合是"所有未标 O 的格"，**包含未知格** → 是乐观距离，不是安全通行保证；
- 两种图必须区分：父子树负责分解历史，局部 TSP 完全图负责访问顺序。
  **TRACE 不是沿分解树做 DFS。**

### 2.4 区域内部覆盖（精读 §7）

1. **未完全探索**：从当前 3×3 邻域选目标，要求属于当前 `R(n)`、状态 `Fu`、直线连接无碰撞；
   按"左侧扫描线 → 当前扫描线 → 右侧扫描线"优先级，同线多候选取最近格，形成往返扫描；
   含 §2.1 的延迟标记规则。
2. **死路恢复**：附近无合法候选但区域未完成时，搜索"邻接已覆盖区域的最近自由未覆盖格"，
   经最短路径到达后恢复扫描。精读指出：原文**没有**给出全部最近距离判据、平局处理
   和"无候选"情形的完整实现细节。
3. **全部探索后**：区域内无未知格时，改为对当前位置访问其每个剩余格做 TSP；
   下一目标区域的中心作为**虚拟终点**，使结束位置便于衔接；无下一目标时固定起点、终点自由。

## 3. 当前信息条件的差异（必须先解决，否则不能称"保留原机制"）

| 原假设 | 本项目 | 影响 |
|---|---|---|
| 环境未知，边发现边规划 | 规划时**当前地图已公开**（`free` 已知） | 树不再由"新发现障碍"驱动，只剩"已覆盖格退出 `R(n)`"这一来源 |
| `U` 未知格与 `Fu` 未覆盖格都在 `R(n)` 里 | 我们只有 `Fu`（= 当前未完成目标 ∩ 自由） | **未知空间收缩为零**；`R(n)` 直接等于未完成目标集合 |
| 分裂由未知→已知的变化触发 | 无未知变化 | 分裂只在"目标被覆盖后剩余集合断开"时发生 |
| 覆盖装置有足迹半径 | 本项目半径 = 0，经过即覆盖 | 每走一步都可能有格退出 `R(n)` → 分裂极其频繁，树更新开销与原文不可比 |
| 覆盖全部自由空间 | 只要求覆盖**已发布目标**；非目标自由格可通行 | `R(n)` 必须只含目标，不能把可通行非目标格算进剩余区域 |
| 机器人终态由局部覆盖/TSP 决定，无固定返航 | 必须返回基地 | 需要"固定终点"适配；原文的"虚拟终点 = 下一区域中心"要替换为基地 |

**结论（必须写清）**：TRACE 的核心是"对**当前剩余空间**做递归连通分解"。
当前模型里"未知空间"不存在，因此 `U` 维度整个消失，树的更新只剩"已覆盖目标退出剩余集合"。
这**不是**把未知空间自动等同于新增目标，而是原机制的一个退化特例。
是否可以称为"忠实适配"，需要先证明在退化情形下树的语义仍然自洽（见 §5 的验证清单）；
在此之前只能叫"TRACE 式分层分解的适配研究"。

## 4. 拟定接口（下一阶段）

```python
# 计划路径：src/adapters/trace.py（本轮未创建）
METHOD_ID = "TRACE"
METHOD_VERSION = "trace_adapt_v0.1_<date>"

def run(request, clock=None, options=None) -> PlanResult
```

输入沿用 `specs/unified_interface.md` 的 `PlanRequest`。额外的必须显式参数：

| 参数 | 含义 | 默认 |
|---|---|---|
| `delayed_marking` | 是否保留原 IV-D2 的"上下仍为 Fu 则暂缓标记 Fc"规则 | `True`（忠于原文），并须单列它对路线的影响 |
| `local_target_window` | 局部候选邻域（原文 3×3） | 1（即 3×3） |
| `order_solver` | 局部/全局 TSP 的近似器 | 共同连接器 + 2-opt；与 LKH 版本分开命名 |
| `virtual_end` | 区域结束后是否用"下一区域中心"作虚拟终点 | `False`；本项目以基地为固定终点，需另写明替代规则 |

输出沿用 `PlanResult`；`meta` 必须包含：树的节点数/叶数、每次分裂的触发原因
（覆盖退出 vs 障碍）、`R(n)` 的连通分量数、每次局部 TSP 的规模与求解器、
以及"延迟标记"实际改写了多少格。

## 5. 下一阶段实现前的验证清单（顺序不可跳）

1. **退化语义微例**：一个 3×3 无未知区的例子，手算 `R(n)`、分裂、`p(n)` 投影，证明树在
   "无未知"时仍按原文步骤产生同样的分裂；
2. **延迟标记的必要性**：构造上下两格仍为 `Fu` 的例子，比较开/关延迟标记的路线，
   证明该规则不是可有可无的装饰；
3. **树边 ≠ 运动边**：证明保留的父子关系不会被当成可执行边（用不可直连的父子对做负例）；
4. **已覆盖仍通行**：已覆盖目标退出了 `R(n)`，但仍可作为通行格；用"必须穿过已覆盖通道"
   的例子验证实现没有把已覆盖格当障碍；
5. **固定返航**：虚拟终点规则替换为基地后，验证终点合法且步数包含返航；
6. **与 `TREE_MST` 的区分测试**：同一微图上两者路线应不同；若相同，说明 TRACE 适配退化成树初始化，
   必须查明原因而不是宣称实现成功；
7. **信息条件**：只使用 `request.free` 与 `request.published_targets`，不读未来扩展。

## 7. 本轮结论

TRACE 可以做当前模型的适配，但**不是**把 `TREE_MST` 改名，也不是"沿树 DFS"。
它是下一轮最重要的结构候选之一；在 §5 的 7 项验证通过之前，不进入方法集合，
更不进入性能排名。
