# 七算法共同预算比较v0.3：版本与协议说明

日期：2026-10-20。本文件解释已在正式运行前生成的`protocol.json`，不修改其中规则。最终完成状态以`execution/completion.json`和只读核验为准，不能用本说明当作已完成实验的证明。

## 目的

在C*任务服务域、知识边界及等价效率修正验收后，重新对照PPCPP和其余算法。整批新运行，不把新版C*单独40次插入旧280次，不据旧适配错误夸大PPCPP优势。

## 固定版本

| 方法 | 本批版本 | 边界 |
|---|---|---|
| P2_MULTI | v2_20261012 | 自建多起点扫描/2-opt工程基线 |
| OARP_CORE2 | v2_20261012 | 冻结模型2，真实旧后缀保底，不是独立RANK0 FULL或完整OARP-Replan |
| TREE_MST | v2_20261012 | 自建树遍历与局部优化，不是TRACE/C* |
| PPCPP | 独立v0.2 | 固定历史方向/捕食者输入，保留已验收原机制，不加旧后缀候选 |
| CSTAR | CSTAR_EQUIVALENT_v0.7 | 当前公开任务域适配及等价提速，不含原生未知地图控制器或跨事件保树 |
| TRACE | public v0.1 | 当前公开任务图适配，非完整未知环境在线控制器 |
| CAP | single_source v0.2 | 已审查的当前任务适配，保留固定终点/重启约定 |

正式之前：20份输入与旧v0.2逐文件哈希一致；49份共有源码/依赖哈希一致；预检C*原始返回明确标记`CSTAR_EQUIVALENT_v0.7`。新C*七份运行文件与其候选冻结记录匹配，冻结及归档清单也纳入本批源码保护。

## 共同条件

- 原20个开发状态（10图族控制/事件），两种子20261018/20261019，七算法，固定280工作项；没有新增留出地图。
- 每次20秒，主计时是预载后的完整入口，从公共请求/对象转换到返回；含入口内原有检查/观测，不含导入、落盘和独立外审。原生自报秒、导入秒和进程墙钟另存。
- 主及时口径：完整合法路线且入口≤20.010秒；另报告严格≤20秒。容差不随结果调整。
- 独立进程串行，常见数值线程设为1；方法顺序按状态/种子轮转、第二种子反转，工作项顺序与原批次相同。
- 同一当前公开F/T/C/P、位置、基地和资源。相同真实初始任务/历史后缀共同提供；独立算法按固定API不把旧后缀当候选。PPCPP历史方向和捕食者固定，不提供未来事件或验证用覆盖见证。
- 不统一修改各算法原生连接器，不额外补全；三种工程基线保留原冻结保底，须单列来源。
- 90秒进程看门狗，连续两次技术故障停止；任何输入/源码或独立审核错误立即中止。逻辑超时/资源拒绝保留，不失败重试、不加预算。
- 正式前7个五格接口预检和6项公共审核契约检查通过。预检不算280次正式成绩。

## 汇总原则

1. 先报告合法率、及时率、迟到及失败，再比较路程。
2. 路程只按同状态/种子且双方均及时配对，未配对不能丢弃。列七方共同交集和可用的全40配对，不在不同成功子集间直接比较总步数。
3. PPCPP作分子逐项计算(PPCPP−对照)/对照，分别列控制/事件及小中大分组；不把反向百分比平均值取负。
4. 两个种子不是独立地图，开发数据不能替代留出；不预设主算法或普遍赢家。
5. 旧批次和C*中间版失败保留；新版比较不能覆盖旧稿，未推送GitHub。

## 证据

`protocol.json`是正式前固定记录；`preflight/`含7次预检、版本/输入契约；`execution/`含正式逐项输入引用、日志、原始输出、审计及时间；`analysis.json`和PPCPP中心文件在结束后从本批输出生成。运行`verify.py`作只读再审，不新增求解。
