# 剩余覆盖路径规划：文献基线、算法比较与OARP研究进展

汇报日期：2026年10月18日。

目前的研究面向这样一个过程：无人机已经完成一部分巡检，随后发现新障碍，或者施工待检区域继续向前、向拐角扩展。无人机需要保留已经完成的巡检记录，从真实当前位置出发，完成所有当前能够巡检的剩余任务，再返回基地。

我们希望研究局部重规划和整体重规划的适用条件，以及局部重规划范围应该怎样确定。这里的局部重规划只调整剩余任务中的一部分，最终仍须完成全部当前可检任务。由于范围实验的结果会受到底层路径规划方法影响，目前先把底层算法的实现和改进方向确定下来，再继续研究范围。

这份汇报按四部分展开：文献采用的基线、无障碍区域的覆盖方法、我们的实现及实验数据、重点研究OARP的原因与当前进展。

## 二、空白无障碍区域可以采用的路径规划方法

### 2.1 这里讨论的是覆盖规划

无障碍只表示不需要绕开障碍，并不意味着任务只是从起点飞到终点。我们的要求是经过每个待检格子，完成向下采集，再返航。单独使用A*、Dijkstra等点到点最短路，只能解决两段覆盖任务之间怎么连接，不能决定全部任务怎样覆盖。

还需要区分两种情况：一是起飞前整片规则区域尚未巡检；二是已经执行了一部分之后，剩下一片或几片无障碍区域。第二种情况多了真实当前位置、已完成任务形成的缺口、新目标与基地衔接，路线组织通常更复杂。

### 2.2 可以考虑的方法清单

| 方法或类别 | 直观走法 | 适合的区域 | 优点 | 在我们场景中的注意点 |
|---|---|---|---|---|
| **牛耕式往返扫描** | 走完一行转到下一行，来回扫完整片 | 规则矩形、长条带、直线扩展区域 | 简单、构造快、路线容易解释 | 横扫或竖扫、先去哪个端点、扫描后的返航都要考虑；不预设某方向一定最短。 |
| **螺旋覆盖** | 沿外围逐圈向内，或从内向外扩展 | 连续、较规则的区域 | 结构清楚，可形成连续覆盖 | 任意当前位置与固定基地返航可能增加连接；部分已覆盖形成缺口时需补充回溯。 |
| **栅格Hamilton路径/回路构造** | 在适当网格中尽量每个目标只访问一次 | 满足形状、连通性与端点条件的规则网格 | 能提供很好的构造或小图最优参照 | 不保证任意缺口、任意起终点都存在；回到区域外基地也会增加步数。 |
| **STC及相关树覆盖** | 建立覆盖树，再沿树组织巡游 | 不规则连通网格、需要可靠覆盖的区域 | 能处理较复杂连通形状，覆盖过程可解释 | 粗细网格尺度、部分占据和历史接续需正确处理；普通MST遍历不等于标准STC。 |
| **单元分解＋区内扫描** | 先分成若干容易扫描的子区域，再安排访问 | L形、拐角、多个连接区域 | 保留每个规则子区的扫描效率 | 区域怎么分、从哪个入口进入、子区之间怎么连接会影响总路长。 |
| **条带划分＋GTSP** | 把格子组成直条带，联合选择顺序与方向 | 规则条带与不规则剩余任务混合 | 用较少服务单元组织大量格子；OARP属于这一路线 | 最少条带数不自动等于最少步数；强制保留旧连接可能限制质量。 |
| **点集TSP/开放端点访问排序** | 直接安排剩余目标的访问顺序 | 分散目标、已覆盖造成较多缺口的区域 | 不要求沿固定条带完整服务，表示更灵活 | 目标多时求解代价上升；图距离、当前点和基地终点要一致。LKH是强启发式，不自动提供最优证明。 |
| **最近邻＋2-opt等局部搜索** | 先连近的目标，再交换访问次序减少绕行 | 需要快速得到路线的多目标任务 | 易实现，可作为透明工程对照 | 对初始化敏感，可能陷入局部最优；P2使用了这类机制并增加了多起点搜索。 |
| **波前/距离场引导覆盖** | 用距离层次安排逐格访问与回溯 | 已知栅格、结构较简单的连通区域 | 规则直观，可与连接器结合 | 需要专门的完整覆盖与回溯规则，单一距离场不等于完整规划器。 |
| **ε*、PPCPP等逐步决策覆盖** | 根据势场或奖励不断选择下一目标 | 规则区和不规则区均可尝试，尤其是在线任务 | 可以逐步更新覆盖状态并处理死端 | 无障碍规则区未必需要复杂决策；须评价真实路线，不能因方法复杂就预判更好。 |

上述属于可用方法类别，不表示我们已经实现并比较了每一类。扫描、螺旋、网格树、波前与TSP这些基本路线可在[OARP-Replan相关工作](https://arxiv.org/html/2311.17837v2#S1.SS1)核对；几何分解和扫描方向联合选择的具体实例见[BCD-GTSP](https://arxiv.org/html/1907.09224v1)。Hamilton条件的表述是网格构造层面的适用性说明，本稿不据此主张任意区域最优。

### 2.3 对当前研究的使用方式

规则矩形无障碍区域可以先使用牛耕扫描作为清楚的基础参照。对于已经部分覆盖、出现新目标或拐角的区域，需要连同当前点、剩余目标形状和返航一起安排，适合比较条带方法与点集访问方法。

这些方法不与后续局部范围研究冲突。范围选择决定哪些旧任务和路线约束允许调整；底层路径规划决定在给定约束下具体怎么飞。本阶段先处理第二件事，不预设空白区域必须采用另一套复杂算法。

## 三、我们的实现、实验条件与效果数据

### 3.1 统一比较的任务口径

所有方法都以四邻接单位移动为基础。一格表示一次有效向下采集面积，不代表道路只能一格宽。已覆盖目标和非目标自由格仍可作为通道；新障碍既禁飞，也遮挡其下未完成目标，受阻目标暂缓，不算已完成。

主要看两个指标：**完整剩余覆盖加返航的总步数、完整规划的计算时间**。计算时间与无人机实际飞行时间分别记录。当前没有真实动力学与能耗模型，因此不把步数直接换算成电量，也不设置未经标定的转弯能耗权重。转弯、重复覆盖、非目标移动可用于解释路线特点。

输出先通过运动、碰撞、覆盖、返航和剩余资源检查。没有合法完整路线不能记为零步。共同保底是额外的安全候选，保底获选不等于方法核心生成了该路线。

### 3.2 已完成的五方法开发比较

## 四、重点研究OARP的原因，以及目前完成的工作

此前已经用同一P2引擎比较过较小局部范围、扩大的局部范围和整体重规划，并检查过旧计划热启动、初始候选保留、先局部后整体等机制。开发数据中出现过中间范围较好的例子，也发现了局部约束造成额外步数、已有短路线没有被搜索找到等不同原因。这些成果保留为范围研究的依据，但还没有形成可靠的范围选择规则。

之所以先转到底层方法，是因为有限预算下的范围优势可能同时包含任务规模、路线约束和求解效率的影响。底层方法改变以后，旧范围优势需要重新检验。若整体与局部都真正求得最优，整体可以采用局部的完整路线，整体最优不会更差；启发式自然结束并不满足这个前提。后续仍会同时研究路线质量和计算时间的取舍。

### 4.1 选择依据

**问题结构接近。**OARP-Replan直接处理已有覆盖计划被新发现障碍打断后的重规划，与我们的执行中剩余覆盖问题联系最直接。我们的目标新增、真实覆盖历史、基地返航和单位步数属于需要明确处理的适配，不能照搬原文结论。

**已有计算开销具备继续研究的价值。**旧OARP核心适配在共同开发状态中能够较快给出路线，路线质量则有改进空间。PPCPP更快、TREE也有较好成绩，OARP不是依据单一时间或总步数获选；当前选择综合考虑问题适配性、结构清晰程度与改进能否验证。

**结构适合后续范围研究。**OARP把任务组织为横纵条带及路径块，便于表达哪些段允许重排、哪些段保留。这是结构上的便利，尚未证明它的局部范围方法已经有效。

**原目标与我们的实际代价存在可检验的差别。**条带数量和少改旧结构有利于原框架控制问题规模，但我们最终评价完整飞行步数。可以分别核查条带划分、路径块绑定、访问顺序造成的影响，避免同时改多处后无法解释收益。

因此，目前将OARP作为重点改进对象，P2、TREE、PPCPP继续保留为比较方法；没有将OARP认定为领域最好，也没有因实现投入较多而取消其他强参照。

### 4.2 条带和连接的具体含义

条带是一段连续直线任务。例如12个格子可以横分为三根，也可以竖分为四根：

```text
横向划分             纵向划分
A A A A              A B C D
B B B B              A B C D
C C C C              A B C D
```

划分完成后，还需选择先走哪根、每根朝哪个方向走，以及从当前点怎样接入、最后怎样回基地。固定两个端点之间已使用网格最短路；研究中的连接选择主要指访问顺序、方向和是否强制保留旧连接。

例如旧计划将A、B绑成一个路径块，新增任务C后只能把C放到整块前后；释放绑定后，就允许考虑A→C→B等顺序。所有段之间仍需合法连通，最终任务量不变。这项变化不等于改变空间局部重规划区域。

### 4.3 先建立可信原生参照

早期OARP_CORE2从P2旧路线恢复直条带，只能说明该恢复接口下的表现。为了检查原方法结构，我们建立了OARP生成初始条带与访问路线、真实执行前缀、发布事件、再重规划的原生闭环。旧条带身份直接来自求解结果与计划注释。

核查时发现并修正了以下问题：

| 问题 | 修正内容 | 作用 |
|---|---|---|
| 反向条带的几何顺序与时间索引混淆 | 规范方向、访问方向和实际区间分别保存 | 不再因反向截取漏格。 |
| 多根条带及弯曲连接被当成一根直条带 | 路径块保存多个原子条带及成员跨度 | 保留原生结构，并能独立审核。 |
| 新障碍出现后才生成旧参考 | 事件前固定参考，事件后另算可检与暂缓目标 | 不会把障碍造成的变化提前删除。 |
| 起点、资源和事件选择口径不一致 | 从基地真实准备，扣执行步数，按冻结规则选旧地图障碍 | 各配置共享同一真实状态。 |
| 最后审核漏计、保底与核心混淆 | 公共截止贯穿，保存候选时刻，分列核心/保底/完整返回 | 路线与耗时的解释更清楚。 |

修复后的有限重跑包括1次新准备、28次事件响应和10项真实接口边界，共39次完整调用。无变化N1的四配置核心均恢复合法8步。28次事件响应最终全部合法，21次有合法核心候选，7次因条带变化额度不足而核心不可行，独立枚举确认了判定。严格N3没有合格未来连接候选，记不适用，没有凑四次响应。

本轮保留条带模型、LP/MIP流程、路径块与GTSP机制，但不包含作者原连续运动、边行驶边计算及完整在线机器人系统。实现中还保留额外认证修复路径，并明确其非原文部分；本批未触发它。以上成果支持当前适配范围的进一步诊断，不扩大为原文全套性能复现。

### 4.4 最新受控实验：分开检查三个环节

随后使用三种固定生成的目标矩形6×3、12×4、24×5，每种设置无变化、障碍、直线扩展、拐角扩展加障碍四种事件。每种只生成一次原生初始计划，执行到首次覆盖50%初始目标，再对同一状态进行两响应种子比较。这些是受控开发用例，不是此前十张道路图。

| 配置 | 条带阶段 | 访问阶段 |
|---|---|---|
| FULL | 无旧条带变化约束，重新划分 | 全部原子条带重新排序、选择方向 |
| ATOMIC | 原生模型2，放宽条带变化额度 | 释放旧路径块连接；是消融配置 |
| PACKED | 与ATOMIC相同模型和额度 | 保留可复用旧路径块 |

3次准备＋12状态×3配置×2种子，共75次完整调用。72次响应的核心和最终路线均合法，核心均按冻结配置自然完成，没有重试、运行异常或软超时。ATOMIC与PACKED的24组配对中，条带划分全部一致，因此可以单独检查旧连接限制。

### 4.5 最新实验的主要发现

| 受控状态 | FULL核心步数 | ATOMIC核心步数 | PACKED核心步数 | 能说明的差别 |
|---|---:|---:|---:|---|
| 12×4无变化 | 27 | 27 | 29 | 保留旧连接也可能增加剩余路程。 |
| 12×4直线扩展 | **41** | **41** | **57** | 同样五根条带，旧路径块限制多16步。 |
| 24×5无变化 | 87 | 87 | 89 | 再次出现同条带、连接约束造成的2步差距。 |
| 24×5直线扩展 | **97** | **99** | **101** | 释放连接省2步，另一种同样五根条带的划分还能再省2步。 |

两个种子的上述步数一致，表中没有把它们算成两种独立场景。其余八个状态三者核心步数相同。按24次响应合计，FULL=1212步，ATOMIC=1216步，PACKED=1260步。

PACKED在12×4直线扩展的最终候选池中选了51步贪心保底，核心仍是57步；因此最终输出合计为1248，而不是1260。核心机制与最终安全输出分别统计。

**第一项发现：旧路径块约束确实能造成代价。**释放连接后，8/24配对更短、16/24相同、没有更长。精确求解确认差距来自固定块限制，而不是GLNS尚未找到已有可行走法。此前微图N4也有16→12步的同类证书。

**第二项发现：本批没有显示访问顺序搜索不足。**21个旧微图核心和72个新响应核心，均达到各自固定结构的精确最优。因此当前不优先增加GLNS搜索轮数或更换LKH。结论仅针对这些服务组较少的用例，不推广到复杂大图。

**第三项发现：同样条带数，不保证同样路线质量。**24×5直线扩展中，FULL与ATOMIC都是五根条带，固定划分最优值却为97和99。只按条带数及少改旧结构挑划分，未必挑到实际步数较短的版本。不过，七个旧微图的全部最少条带划分均能达到对应覆盖最优，说明这个问题有场景边界。

成对比较，PACKED较ATOMIC有22/24次更快，但较FULL仅5/24更快，19/24更慢。三个单独中位数无法替代同任务配对。12×4直线扩展中，PACKED比ATOMIC两次运行的中位耗时只节约约0.81毫秒，核心却增加16步；本例没有显示值得采用的取舍。数据中存在单次时延波动，两种子不足以确定稳定加速比例。

目前尚未实现新的代价驱动算法，也不把简单多候选择优直接称为创新。方案确定后再在道路开发输入上验证；暂不追加矩形规模、cap或随机种子追正例。

## 附录C：文中术语的简要解释

| 术语 | 本稿中的含义 |
|---|---|
| 覆盖规划 | 安排经过全部待检目标的完整路线；不只是两点之间找最短路。 |
| 条带/rank | 连续的一段横向或纵向直线任务；这里的rank不是优先级排名。 |
| 路径块 | 一根或多根条带连同旧连接组成的整体，保留时内部走法受到约束。 |
| GTSP | 广义旅行商问题。在本实现中，每根条带或路径块有两个行驶方向，要从每组选择一个方向并确定访问顺序。 |
| GLNS | 用于求GTSP路线的启发式求解器；结束搜索不自动证明最优。本轮通过另一个精确算法核对小问题。 |
| LP/MIP | 连续变量优化与含整数变量的优化求解方式；用于求条带划分，结果还需解码为合法格子与条带。 |
| 2-opt | 改变访问序列中的两处连接，尝试去掉绕行的一种局部优化；不能保证找到全局最优。 |
| 核心路线 | 该方法自身主要构造流程生成的路线。 |
| 保底路线 | 旧尾段或简单贪心等共同备用候选，合法且更短时可以被选为最终输出。 |
| 固定结构最优 | 条带或路径块已经固定后，访问问题的最短路线；不是所有可能划分与全部覆盖走法的最优。 |
