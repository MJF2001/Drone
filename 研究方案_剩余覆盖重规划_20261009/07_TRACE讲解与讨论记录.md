## 2. 一句话理解TRACE

根据剩余未覆盖空间的连通性变化，递归分解区域，形成层次覆盖树；再以这棵树为基础，增量安排区域访问顺序，并生成区域内部的覆盖路线。

树不是最终运动路径，而是组织规划问题的结构。

## 3. 为什么需要这套方法？

如果机器人只根据附近哪个格子没扫来选择下一步，可能留下分散的小片区域。当前局部运动看起来合理，但最后要长距离折返补扫。

TRACE不仅问“附近下一格怎么走”，还问：

1. 全局还有哪些区域没完成？
2. 这些剩余区域有没有分裂？
3. 应该先完成哪块，再去哪里？
4. 当前这一块从哪里结束，方便衔接下一块？

这是作者的问题定位，不意味着所有其他算法都只看局部，也不证明TRACE在所有地图上更好。

## 4. 第一部分：根据连通性递归分解剩余区域

### 4.1 栅格有四种符号状态

| 符号状态 | 含义 |
| --- | --- |
| U | 未知，尚未观测清楚 |
| O | 障碍 |
| Fu | 自由且未覆盖 |
| Fc | 自由且已覆盖 |

剩余区域包含U和Fu，移除O和Fc。因而既可能由于新发现障碍而分裂，也可能因为完成覆盖而分裂。

重要细节：IV-D2有延迟标记规则。当前格若在本条扫描线上上下两格仍为Fu，会暂时保留为Fu，以维持扫描结构。因此符号状态带有规划控制用途，不总等同于实际物理覆盖记录。

### 4.2 从一整块到多个子区域

开始时整个工作空间是根节点。更新地图与进度后，对受影响叶节点的剩余区域做四邻接洪泛搜索：仍是一块就更新信息；分成多块则创建子节点。

下面是解释用示意，不是论文实验结果：

```text
开始：             后来：                 再后来：
   R                  R                     R
                   ┌──┼──┐               ┌──┼──┐
                   A  B  C               A  B  C
                                           ┌┴┐
                                          B₁ B₂
```

节点保存创建时固定的所属子区域、当前剩余区域、代表中心及完成/探索状态。父节点保留分解历史，当前活动叶节点代表需要继续处理的剩余子区域。

### 4.3 两个容易误解的地方

第一，树边表示父区域分成子区域，不表示机器人应该沿着树边移动。TRACE不是简单做一次树的深度优先遍历就得到实际覆盖路线。

第二，剩余区域彼此断开，不等于整个自由空间不可通行。连接两块待扫区域的窄带如果已经扫完，会退出剩余集合，但仍可能作为通行路线；经过它就会产生重复行驶。

## 5. 第二部分：局部更新区域访问顺序

原顺序如果是：

```text
A → B → C → D
```

B分成B₁、B₂、B₃后，TRACE保留其他区域的相对顺序，主要求解：

```text
A → [B₁、B₂、B₃怎样排列？] → C → D
```

具体步骤：

1. 用各子区域的代表中心表示区域；中心不在剩余区域时，调整到其中最近格子。
2. 用A*计算代表位置之间的最短路径距离。
3. 以前驱、后继作为衔接条件，构造子节点局部TSP。
4. 用2-opt启发式改善顺序，替换B原来的位置。
5. 已完成节点从访问序列删除，未受影响节点保留相对顺序。

2-opt的通俗理解：尝试更换两条连接、重新组织中间序列，如果路线更短就接受，按停止规则继续改进。它不是机器学习，也不保证找到全局最优。

必须补充：A*使用的是尚未标记为障碍的格子，包含未知格。所以这是当前认知下的乐观连接距离，不意味着已经确认整段真实道路可安全通行。

这一步的取舍是：局部更新减少计算与顺序反复变化，但可能错过需要跨区域重新排列才能得到的更短路线。代表中心之间的距离也不能完全反映区域内部覆盖的代价。

## 6. 第三部分：区域内部怎样覆盖？

### 6.1 尚有未知格：规则式往返扫描

在当前3×3邻域中选择属于目标剩余区域、状态为Fu且直线连接无碰撞的候选格。按左侧扫描线、当前扫描线、右侧扫描线优先，同线有多个候选时选最近格，形成往返扫描。

注意：分裂检查采用四邻接；局部候选来自3×3邻域并检查直线碰撞，不能把两者混为同一个邻接规则。

### 6.2 附近没得扫：死路恢复

局部无合法候选，但目标区域尚未完成时，寻找邻接已覆盖区域的最近自由未覆盖格，经最短路径到达后恢复扫描。

这是覆盖任务中的死路，不一定是机器人被障碍完全困住。经过已覆盖区可以恢复作业。

### 6.3 区域全部看清：改用局部TSP

“全部探索”表示没有未知格，不表示覆盖已经完成。

此时从当前位置出发，构造访问该区域全部剩余格的TSP。若后面还有目标区域，把下一目标区域中心设为虚拟终点，引导当前路线在方便衔接的位置结束；若没有下一目标，则终点自由。

所以TRACE不是始终牛耕，也不是始终求全局TSP，而是按区域探索状态切换策略。

## 7. 三部分怎样形成闭环？

```text
传感器信息＋覆盖进度
        ↓
更新栅格符号地图
        ↓
定位受影响叶节点，检查剩余区域分裂
        ↓
更新层次覆盖树
        ↓
替换分裂节点、删除完成节点，增量更新访问顺序
        ↓
选择当前目标区域
        ↓
未知尚未消除：规则式往返扫描＋死路恢复
已全部探索：考虑下一目标衔接的局部TSP
        ↓
执行并继续观测，循环更新
```

树负责分解关系，访问序列负责区域顺序，局部规划负责实际区域覆盖，A*承担相关最短连接计算。不能用其中任何一个对象替代整套算法。

## 9. 主要工作、创新与证据边界

原文明示的贡献：

- 层次覆盖树表示剩余空间的连通变化。
- 只更新分裂影响的访问片段，保留未受影响顺序。
- 死路恢复与兼顾下一目标的局部覆盖。
- 仿真和地面机器人验证。

完整覆盖分析依赖固定、有限、自由空间可达及局部执行推进等前提，不是有定位误差时仍无漏覆盖的保证。

近似界针对区域代表节点的访问路线，不是整条实际覆盖路径，且不是统一常数近似比。距离随地图更新而变化等因素的证明处理不充分，详见严格核查笔记。

平均计算约10^-2秒是作者在指定配置下的报告，不是最坏情况实时保证。与OARP-Replan不同，本文没有给出同类显式遇障计算预算和超时降级机制。

## 10. 实验应怎样理解？

6个仿真场景与1个实验室地面机器人场景，直接在线比较5种方法：BINN、BA*、ε*、PPCPP、IBINN；另有离线TSP参照。

实验支持所给场景的效果，但需要注意：

1. 没有直接比较C*、CAP或OARP-Replan。
2. 并非每场景每项指标都严格最好，例如森林场景BA*转弯量更低。
3. 没有看到拆除各模块的消融验证，无法单独量化分解树、增量排序与局部TSP各自贡献。
4. 用LKH构造的离线参照没有提供最优性证书，不能直接视作已证明的全局最优。
5. 有噪声实验的真实覆盖率不全为100%；理想定理不替代误差下实验结果。
6. 地面机器人验证不能直接代表无人机、施工道路或区域扩展验证。

具体参数、证明审查与实现信息缺口统一记录在06号严格核查文件，避免本笔记把作者结论当成已独立验证的事实。

## 11. 和第一篇的区别

| 比较项 | OARP-Replan | TRACE |
| --- | --- | --- |
| 主要组织单位 | 新覆盖条带和保留旧路径段 | 剩余区域及其层次分解 |
| 结构更新 | 重划条带，并复用旧段 | 连通分裂后建立子节点 |
| 访问规划 | GTSP选择单元顺序和行进方向 | 局部TSP替换分裂节点，保留其他区域相对顺序 |
| 区域内部作业 | 以直线条带为基础 | 未完全探索时往返扫描，全部探索后局部TSP |
| 计算时限 | 显式利用遭遇位置时间预算，预算不足用GD | 报告平均速度，没有同类显式截止机制 |
| 相同限制 | 不保证整条实际覆盖路线全局最优；没有直接验证我们的待检区域真实扩展 | 同左 |

不能仅凭这张机制表判断谁性能更好，必须统一信息、覆盖与运动模型后实测。

## 12. 对我们的研究：哪些已知，哪些尚未成立？

已知：递归分解剩余空间、局部更新访问顺序、覆盖结束兼顾下一目标，都值得学习，但属于本文已有机制，不能原样作为我们的创新。

机制推断：真正新增道路可能连接已有分支，因而只分裂的结构不一定足够；本文没有给出对应合并和扩容规则。这里的树扩展指创建子节点，不能与道路区域扩展混用。

尚未成立：分裂与合并是否足以形成论文创新、是否比简单剩余重算更省路径、计算收益是否明显，均需继续读其他工作并实验验证。
