# 小规模固定采集位置精确排序协议

日期：2026-10-10。执行前声明，探索用途，不是新算法或独立留出实验。

1. 输入为run_11_fixed_domain_v2的全部64个快照，不按性能选例。分别检查共同H/V采集位置生成器的完整点池。点数≤14的池运行精确动态规划，超过14全部保留并标记size_limit，不截取点集或删覆盖目标；0点也处理。
2. 精确问题：起点和基地固定，在当前地图A*最短距离下访问给定池中所有点，终点为基地。状态DP[S,j]表示从当前点出发访问集合S并结束于j的最短代价，递推枚举上一个点，最后加返航距离。复杂度O(n²2^n)，只在完整DP结束后称精确；单池30秒上限，超时不报最优。
3. 比较同一点池内的蛇形初解、最近邻初解、各自最多8轮2-opt（既有P2的四种候选），报告其中最小代理距离与精确值。完整P2还会比较两个池及合法旧后缀，不能把单池候选说成完整P2。
4. 代理目标是必须访问所有给定点的距离和，不是允许改变采集位置、利用途中覆盖的面积覆盖全局最优值。不能用它作为面积覆盖路线的下界或宣称得到全局最优覆盖。
5. 每个访问顺序另用共同执行规则独立展开：每条顺序从空A*缓存开始，沿途采集、跳过足迹已覆盖的点、返航。精确代理顺序的实际路线可能比启发式更长，照实保存。A*等长路径的选择及途中覆盖是模型的一部分。
6. 提取P2候选时按现有rebuild原顺序执行，先保存实际路线，不能额外查询距离污染其缓存。代理评分与规范化展开在另一个Geometry中执行。检查提取候选加旧后缀的最佳实际长度与run_11存储P2结果一致，不一致即报告并排查。
7. 可额外统计“在原有规范化候选中增加精确代理顺序”是否改善实际路线，这只是候选集合增加，不把精确顺序强行替代更好启发式，不称创新。
8. 保存原输入、所有顺序、代理代价、实际路线、失败/超时及源代码。精确参照使用额外离线计算资源，不作与5秒P2公平运行时间比较。相关池和地图共享历史，计数不视为独立随机样本。
