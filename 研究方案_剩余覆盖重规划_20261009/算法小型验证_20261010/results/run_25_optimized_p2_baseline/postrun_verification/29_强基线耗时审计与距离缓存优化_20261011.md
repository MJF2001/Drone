# 强基线耗时审计与距离缓存优化

日期：2026-10-11。承接28号报告。本轮做了两件事：定位P2计算开销；用相同覆盖规则对比两种距离计算实现。**没有提出新的覆盖规划算法。**

## 1. 结论先行

原P2已经有点对路径缓存，不是每次距离查询都重新运行A*。问题在于最近邻排序需要大量首次点对搜索，2-opt又有大量缓存查询。将首次点对距离改为按起点批量BFS，并保留原A*实际路径的选择规则后：

- 24个既有快照，4个预算、2种实现、2次重复，共384次求解，全部得到合法的完整剩余覆盖返航路线。
- 5秒和20秒下的192条输出，均与旧版20秒路线逐点一致，不只是步数相等。
- 20秒档位实际计算总用时由47.238秒降至17.648秒，降低约62.6%，约为原来的37.4%；总步数完全相同。
- 0.1秒预算下，总步数7700→7424，减少276步，约3.58%；0.5秒下7396→6944，减少452步，约6.11%。

这证明旧版短预算的部分损失可以用工程优化改善。因此，不能直接把旧版短预算差距当作新的覆盖算法的创新依据。

## 2. 实验A：分阶段审计

### 方法

复用run23的24个冻结快照。按原P2的候选产生顺序执行，分别记录几何初始化、共同保底路线、横纵候选、最近邻、2-opt、路径展开、合法性检查的耗时，并保存每次候选出现时刻、是否改善当前最好路线。

设置60秒诊断预算；每个快照运行一次。加入调用计数与计时会增加开销，**其耗时不能与未插桩的公平对照混用**。24条最终路线均与旧版未插桩20秒路线完全一致。

### 结果

| 阶段 | 插桩累计耗时 | 占被记录阶段总耗时 |
|---|---:|---:|
| 最近邻排序 | 17.978秒 | 49.79% |
| 2-opt | 17.583秒 | 48.69% |
| 路线合法性检查 | 0.413秒 | 1.14% |
| 路径展开 | 0.104秒 | 0.29% |
| 其余 | 约0.032秒 | 约0.09% |

24例合计：距离调用11,700,002次；路径接口调用11,724,505次；其中206,512次未命中缓存，11,517,993次命中缓存。未命中次数与记录的A*搜索数一致。

路径接口累计24.039秒是上述阶段内部的嵌套时间，**不能再加到36.110秒的阶段总和上**。计数尤其会放大海量轻量缓存查询的开销，因此49.79%/48.69%只是插桩版本的归因结果，不能视为原程序精确占比。

## 3. 实验B：不改变覆盖规则的工程优化

### 两种实现

- `P2_ASTAR`：原Geometry，首次点对查询运行A*，保存路径并复用。
- `P2_BFS`：需要新距离时，按起点延迟建立到所有可达格的BFS距离表；实际输出连接路径仍使用原A*。

无权四邻接图中，BFS与A*给出相同最短距离。特别处理了最短路并列问题：原程序在第一次请求某个点对时确定A*路径及反向缓存；新版记录第一次请求方向，真正需要路径时按该方向调用原A*。否则，即使距离不变，经过哪些待检格也可能改变，不能声称保留原算法行为。

两版采用相同候选顺序、最近邻与2-opt规则、共同保底路线、覆盖检查、返航要求与协作式软时限。只注入不同Geometry类。原默认实现保留，便于重现实验；以后使用优化版需要显式指定。

### 协议

- 24个冻结快照；预算0.1、0.5、5、20秒；每组合2次重复。
- 实现顺序交替，预算顺序轮换并在第二次重复时反转。
- 不插桩，保存全部路线、状态、实际计算耗时及输入/源码哈希。
- 20秒结果运行时检查与旧版参考路线逐点相同；事后独立核验同时检查5秒档。
- 这是开发场景上的配对实现对照，既不是新测试集，也不是现场时限验证。

### 结果

每个预算每种实现48次执行，来自24个快照×2次重复，不能写成48个独立场景。

| 预算 | 原版总步数 | 优化版总步数 | 优化版更短/相同/更长 | 原版/优化版实际用时中位数 |
|---|---:|---:|---:|---:|
| 0.1秒 | 7700 | 7424 | 26 / 22 / 0 | 0.1000 / 0.1000秒 |
| 0.5秒 | 7396 | 6944 | 22 / 26 / 0 | 0.5000 / 0.2613秒 |
| 5秒 | 6768 | 6768 | 0 / 48 / 0 | 0.6080 / 0.2588秒 |
| 20秒 | 6768 | 6768 | 0 / 48 / 0 | 0.6173 / 0.2581秒 |

0.1秒档13个快照在两次重复中都改善，11个都相同；0.5秒档11个都改善、13个都相同，没有重复间胜负翻转。优化版20秒档的最长实际用时1.829秒，原版4.881秒。

20秒档的48次优化版与原版配对：路线完全相同，计算总用时降低约62.6%。这不是“让无人机少飞62.6%”，也没有计入等待引起的电量消耗。

384次求解全部合法；没有超过预算10毫秒以上的记录。达到时限的求解均已保留合法路线，不能将`planned_at_timeout`解释为巡检失败。计时沿用共同求解框架，结果后的独立审计不计入求解时间；软时限不是实时系统硬截止保证。

## 4. 如何更新我们的研究判断

1. **已经证实：实现效率会明显改变短预算路线质量。** 原来观察到的时间压力不能全部归因于规划思想。
2. **仍有线索：优化版0.1秒下比自身充分预算多656步；0.5秒下多176步。** 但这些差距可能继续通过常规搜索顺序、剪枝和实现优化缩小，不能预定为论文创新。
3. **长预算的步数改进空间没有被消除。** 新旧版路线相同，也都不是已证全局最优。run23每个场景最好已知可行路线合计3336步，P2充分预算单次合计3384步，已有48步可行改善，但不保证同一在线算法能稳定取得。
4. **不能直接用本轮优化版与上轮STRIP时间表宣称胜负反转。** 输入一致但运行批次不同。本轮只是原版/优化版P2配对；下一次方法间比较应在同一批运行中，统一合理的距离计算基础设施。
5. **BFS距离缓存不是本论文创新点。** 没有增量维护覆盖分解、复用多事件历史或设计新的剩余覆盖优化机制。也未测内存消耗；不声称降低内存。

## 5. 核验与复现入口

独立脚本重算了输入历史与目标账本、障碍关系、所有路线的覆盖与返航、归档哈希、组合完整性和配对统计；run24的候选改善轨迹、计数关系及阶段汇总也核对通过。run24为24条，run25为384条，均0错误。另有6项回归测试通过，包括1200次交错距离/路径查询、全部点对路径核对、完整搜索路线一致性、共同候选有效性和失败统计规则。

核验通过证明当前记录内部一致和路线符合模型，不等于对所有未来地图的正确性证明，也不证明计时可跨硬件复现。
