# 首轮小型验证实验协议

日期：2026-10-10。状态：可审核草案；尚未冻结参数、编写原型或生成实验结果。

当前范围以[论文主题](02_论文主题与具体研究问题.md)为准。只比较环境更新后的完整剩余覆盖路线，不建设真实无人机系统。首批原型见[10号文件](10_首批完整算法原型定义_20261010.md)。

## 一页核心协议

| 项目 | 已确认内容或本轮建议 |
| --- | --- |
| 核心问题 | 新增待检道路或新障碍公开后，从当前位置利用既有覆盖进度，完成剩余覆盖并返航，减少移动长度。 |
| 第一轮实验方式 | 建议固定同一事件后快照：各算法收到相同当前位置、已完成目标、旧剩余路线、地图和新增任务。求解期间位置固定，独立报告计算时间；不宣称已实现飞行中并发重规划。 |
| 空间与动作 | 建议二维整数网格、四邻接单位移动，距离单位为归一化格长，不换算真实米、分钟或电量。 |
| 目标与通行 | 分开保存目标地面R、已完成地面C和可飞空间F。剩余目标U=R−C；已覆盖位置仍可合法通行。障碍更新F，不自动删除U。 |
| 采集规则 | 建议有效采集位置的固定矩形足迹V(x)，执行器按每到达一个合法格点采集；足迹与当时已发布目标相交计入覆盖。转场经过也按同一规则采集，所有方法一致。具体足迹尺寸是待冻结参数。 |
| 采集简化 | 主模型为理想几何覆盖；飞行禁入与视觉遮挡分开。若只模拟禁入，则明确无额外遮挡，不解释为所有实体障碍都可透视。存在遮挡的压力案例要显式提供不可观测目标，不能暗中改变采集规则。 |
| 历史进度 | 同一条共同初始路线按给定完成比例产生快照，不能为每种算法分别挑有利起点。真正新发布目标不追认事件前的偶然飞越为已完成。 |
| 扩展事件 | 首批连通的直线延伸和直角拐弯；直角是首轮离散简化，不代表研究最终只允许直角。事件前不向算法泄露新目标。 |
| 障碍事件 | 新增后保持静态，发生与公开同步；不能生成在当前位置瞬间占据机器人的情形。路线失效、连接变化、不可达分别记录。 |
| 完成条件 | 规定剩余目标全部几何覆盖、动作合法、无碰撞越界、回到统一基地、满足共同资源预算。允许已完成地面重访但计入长度。 |
| 资源 | 首轮用足够宽松的统一距离预算隔离路径质量，不能冒称真实电池模型；预算紧约束留作后续。 |
| 输出 | 完整后续路线、状态、未完成目标、长度及求解耗时。所有成绩由独立执行审计重算，不相信算法自报覆盖率。 |
| 主指标 | 同快照下完整覆盖并返航的移动长度。未完成的短路线不能排在完整路线前面。 |
| 辅助指标 | 求解总耗时、重复移动、转弯、失败类型；计时含地图/图更新、连接计算和排序。统计平均及尾部，不只报最优一次。 |
| 信息条件 | 仅当前已公开地图与事件；不访问未来事件或真值中未公开部分。不比较谁的感知信息更充分。 |
| 判断边界 | 原型对照不等于原论文复现；启发式全量重算不是最优值；小实验不证明创新或真实巡检效果。 |

## 首轮输入安排

先用一位置覆盖一格的退化模型检查执行器、历史账本和返航逻辑。这一阶段仅调试，不用于路线优劣结论，因为它会削弱采集位置选择与扫描方向的实际意义。

用于候选比较时切换到统一有限足迹模型，建议先试3×3归一化目标格足迹并检查边界行为，再冻结采样间距与其他尺寸；该数值只是方便分析的仿真假设，没有真实相机标定依据。所有原型必须支持同一足迹，不能一个用点访问、另一个用面积覆盖。

| 输入类别 | 首先回答的问题 |
| --- | --- |
| 无变化 | 是否无故破坏已有合理路线？ |
| 直线延伸 | 简单插入新增任务是否已足够？ |
| 拐角延伸 | 是否需要改变扫描方向或进入位置？ |
| 普通障碍 | 修复连接能否解决主要问题？ |
| 关键连接受阻 | 是否需要更大范围调整访问顺序？ |
| 独立不可行案例 | 能否诚实保留未完成目标，不误报100%？ |

每类至少检查不同事件位置和早/中/晚进度。正式实例数量、随机种子与求解预算在实现前列入配置并保存；此时不虚构已完成实例。先不做大量连续事件，以免前序执行差异掩盖单次重规划机制。

## 如何区分环境不可行和算法失败？

在首轮有限格点、理想静态足迹模型中，先求当前位置可达的采集位置集合；若某目标不在任何可达位置的足迹中，或基地不可达，可据此证明该模型下不具备完成条件。无资源紧约束时，若所有目标可由同一可达分量中的位置覆盖，允许重访可构造一条覆盖路线。

找不到满足有限资源预算的路线不能直接宣布环境不可行，除非有可靠下界或精确判定。应区分超预算、求解失败、覆盖遗漏和已证明的不可达。禁止删掉未完成目标提高完成率。

## 候选筛选规则

前两种工程原型先用于检查共同评价框架；随后接入另外两种。不是限定只能研究四种，发现明确的新假设可以增补候选，但登记原因并保证相同实验条件。

探索实例可调试和改算法；确认实例必须在规则冻结后再运行。确认集应含新布局而不只是随机种子变化。看过结果后再调规则，则该批结果降为探索结果。

先比较完整路径，再以关闭机制的版本核查收益来源。允许结论是“简单方法足够”或“没有明显赢家”。不事先承诺提升比例、不以一张有利地图定胜负。

## 实现前需要冻结的项目

1. 有限足迹尺寸与采样间距；以上3×3为建议，不是用户已确认的物理条件。
2. 允许通行范围相对道路的宽度、基地位置，以及首批障碍对应禁入还是同时遮挡。
3. 地图尺寸、初始路线生成规则与事件进度点。
4. 公共排序器的初始化、迭代停止规则、运行预算及计时重复方式。

这些是短小实验协议的具体化，不扩展论文题材。冻结时记录选择理由与适用边界。
