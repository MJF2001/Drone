# 固定条带下，保留旧路径段是否增加剩余覆盖步数？

日期：2026-10-10。探索性机制验证，非创新性结论，非 OARP-Replan 原论文完整复现。

## 1. 结论先说

**本轮发现了一个明确但局部的改进来源：同一组条带中，把旧路径段拆开，允许条带独立排序和选择方向，可以减少部分实例的步数。**

两个条带模型各64例，均为12例改善、52例相同、0例变差；各减少116步。它们在62/64例中得到完全相同的条带划分，因此不能把两组结果当成128个独立场景。

但是，拆分后的方案相对 P2 牛耕重建基线仍然输多赢少。第二个模型加共同备用路线后为：11例更短、26例相同、27例更长。总步数略低主要依赖少量大幅改善实例，尚不足以选定论文算法。

## 2. 这轮究竟改变了什么

输入直接冻结第21份报告对应 run16 的64个单格采集快照，以及两个模型分别输出的条带。没有重新优化条带，没有改变当前位置、已完成覆盖、障碍、待检目标、返航位置或资源预算。

| 对照项 | 保留旧路径段 PACKED | 独立条带 SPLIT |
|---|---|---|
| 条带划分 | 原样冻结 | 完全相同 |
| 未改变的旧条带 | 若原本连续，就作为一个整体访问 | 每条独立访问 |
| 整体内部路线 | 保留旧连接路径与相对顺序 | 可以改用新的最短连接并重新排序 |
| 方向 | 整个路径段正向或反向 | 每条条带分别选择方向 |
| 求解器 | 作者维护的 C++ GLNS，default 配置 | 相同 |
| 随机种子 | 1000 + 场景编号 | 相同 |
| 计算预算 | 每次 TOUR 最多5秒，软限制 | 相同 |

先比较两种**纯核心路线**；再分别与完全相同的旧路线、GD场景备用路线取最短，比较实际输出。备用路线不是原作者提供的实现。

注意：这不是仅改变“访问顺序”的单因素实验。拆分同时取消了旧段内部连接路径的固定约束。结果说明这一组约束存在代价，不能独立断言116步全部来自排序改变。

本轮5秒只用于 TOUR，不含条带优化与备用路线生成。不能直接与上一轮总算法时间作速度比较。

## 3. 结果

| 指标：每组64例 | 模型1 | 模型2 |
|---|---:|---:|
| SPLIT 更短 / 相同 / PACKED 更短 | 12 / 52 / 0 | 12 / 52 / 0 |
| PACKED 纯核心总步数 | 10232 | 10228 |
| SPLIT 纯核心总步数 | 10116 | 10112 |
| PACKED 加共同备用路线总步数 | 10192 | 10188 |
| SPLIT 加共同备用路线总步数 | 10076 | 10072 |
| P2 总步数 | 10144 | 10144 |
| SPLIT 加备用路线对 P2：胜 / 平 / 负 | 11 / 24 / 29 | 11 / 26 / 27 |

模型2总步数相对 P2 低72步，约0.71%。但收益最大的三例分别节省120、120、88步，合计328步。去掉这三例，剩下61例反而合计比 P2 多256步。**因此，汇总略优不代表大多数场景都好，也不是稳定优势。**

一个容易理解的案例：`v3_open_corner_L18_W6_p75`。

- 冻结8条条带；原方法合并为7个访问块。
- 保留旧段需要154步；拆开后138步。
- 两种固定块模型均经独立精确求解，最优值确实分别为154和138。
- P2仍只需130步。说明旧段约束解释了16步，但没有解释剩余8步。

模型2各类事件中，拆分带来的步数减少为：拐角扩展60步、拐角扩展加障碍24步、远处障碍20步、近处障碍12步；其余事件为0。这里的类别各包含8个构造快照，不是现场发生概率。

## 4. 验证做到什么程度

- 共128组配对、256条路线，全部通过独立合法移动、碰撞、覆盖、返航、资源与暂缓目标检查。
- 独立 BFS 重算连接距离，并核对完整块服务成本与实际路线步数：0错误。
- 212次固定块问题可在不超过12个块的规模内精确求解，GLNS在这些实例上均达到精确值。
- 其中100组配对两种模型都可精确求解；拆分最优值均不大于保留旧段最优值。每个条带模型中有10组严格改善。
- 128次 PACKED 重跑全部复现上一轮纯核心步数；共同备用路线组合也全部复现上一轮最终步数。
- 本轮无超过预算10毫秒的执行。仅运行一次，不能由此宣称可靠实时性或统计速度优势。
- 输入、执行代码已保存并校验 SHA-256。首次启动遇到 JSON 坐标为列表的加载错误，尚未产生结果；修正为元组后完整重跑。失败目录保留用于追溯。

精确最优仅限于**固定条带/路径块、每个块完整执行一次**的模型，不是全局格级覆盖最短路线。条带途中可能被连接路径提前覆盖；当前核心解码仍完整执行后续条带，P2 的 `expand` 会跳过已被覆盖的访问点。这是尚未隔离的机制差异。

## 5. 独立判断与下一步

**值得继续研究的是“如何适度解除旧路径约束”，而不是直接宣布“拆开所有条带就是创新算法”。** 后者增加优化自由度，理论上不劣的方向本身很自然，而且目前收益有限、场景依赖明显。

现在不建议立即叠加树、学习模型或更多调参。下一步应针对仍输给 P2 的代表实例，检验“途中已经覆盖，后面仍强制完整执行条带”是否造成额外重复。继续冻结任务、条带和访问解，单独比较原始完整执行与安全跳过已覆盖服务；不得删除尚未完成目标。只有定位清楚后，再决定是改条带划分、执行规则，还是访问排序。

之后需要新增未参与设计的地图、多个种子及更大规模，检验目前的局部收益能否保持。上述64例已经参与方法分析，不能再称独立测试集。
