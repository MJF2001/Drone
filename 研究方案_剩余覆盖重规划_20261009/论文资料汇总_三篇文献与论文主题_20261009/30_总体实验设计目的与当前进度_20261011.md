# 总体实验设计、目的与当前进度

更新：2026-10-11。本报告基于现有代码、实验记录及20—29号报告。本轮新执行的是run24耗时审计、run25实现优化对照及相关核验；此前实验结果引用已有归档，没有宣称全部重新运行。文献状态依据本地阅读和实现材料，不构成本轮新做的文献检索。

## 一、当前结论与阶段定位

**我们已经完成问题收窄、单格采集模型修正、实验平台与强基线建立、OARP核心适配、若干候选机制对照、微型全局最优校验以及计算瓶颈审计；尚未得到经独立新场景验证、具有明确新颖性的论文主算法。**

最重要的发现有三条：

1. 简单地“保留旧路径”“条带加图树”不能保证更省步数，已有候选在新场景的充分预算比较中多数不及P2。
2. 当前微型场景中P2几乎总是全局最优，继续在这些图上调算法，能获得的收益很小。
3. 中等规模短预算下确有路线质量损失，但本轮常规距离缓存优化已消除其中一部分。基线实现必须先合理优化，才有资格判断新算法的价值。

因此，现阶段是**算法研究中的基准建立和候选筛选阶段**，不是论文结果已经齐全、只差写作的阶段。实验做得多，不等于创新已经成立。

## 二、我们究竟研究什么

论文主题沿用已确认的：

> 施工待检区域扩展与突发障碍条件下的无人机剩余覆盖路径重规划方法研究。

问题是：无人机已经完成部分覆盖，正处在真实当前位置；新增待检道路，或者新出现的障碍使旧路线失效。如何利用已有覆盖进度，更新剩余覆盖路线，减少完成剩余巡检及返航的移动代价？

两类事件是：

- **区域扩展**：加入直线延伸、拐角新增等待检格。
- **突发障碍**：更新不可飞入格，也遮挡其下方待检路面；可与扩展同时发生。

我们研究的是信息更新后的路径决策，不开发视觉识别、飞控或完整巡检系统，不把复检调度、多机协同、未知空间探索一起加入。施工背景给出问题来源；目前没有现场数据证明事件频率、必须响应的秒数或实际节电比例。论文应明确是算法仿真研究。

## 三、当前实验模型与边界

| 项目 | 已实施定义 | 解释与限制 |
|---|---|---|
| 运动 | 二维四邻接栅格，每次移动一格计一步 | 不含三维轨迹、动力学和连续避碰 |
| 成像 | 只采集正下方一个格，`radius=0` | 到达待检格即满足抽象采集要求；不仿真视觉误差 |
| 覆盖历史 | 由事件前实际走过的路径计算 | 不凭空指定覆盖比例，也不因重规划清零 |
| 当前位置 | 事件前执行路径的末端 | 不从基地重新起算 |
| 目标变化 | 更新已发布待检格集合 | 新增格在事件后才进入算法输入 |
| 飞行域 | 当前批次采用固定、已知的合法域，再扣除障碍 | 待检区域扩展不等于飞行域扩展；开放域允许从道路旁合法格绕行，走廊域限制绕行空间 |
| 障碍信息 | 事件更新时向各方法提供相同障碍格 | 不向某方法提前透露未来事件，也不仿真相机局部遮挡发现过程 |
| 遮挡目标 | 未完成且被障碍占据的目标保留为暂缓项 | 不要求飞入障碍，不把这些格算成已完成 |
| 合法结束 | 覆盖全部当前可执行目标并返回基地 | “完成”指可执行集合，不等于遮挡路面也已检查 |
| 资源 | 使用统一、宽松的步数上限，通常为飞行域格数的4倍 | 尚非由真实无人机续航标定的电量模型 |
| 重规划方式 | 主要为单次事件后的冻结状态求解 | 尚未完成多事件连续闭环仿真 |
| 计算预算 | 协作式总软时限，保留最好合法候选 | 不等于已验证的板载硬实时期限 |

目标账本的关键关系为：

```text
暂缓目标 =（已发布目标 − 已完成目标）∩ 障碍
当前待覆盖 =（已发布目标 − 已完成目标）− 障碍
```

已经完成的格即使后来被障碍占据，历史记录也不被删除。实际飞行可以经过已经覆盖的合法格，但不能穿障碍。

早期“侧边能拍到邻格”的3×3采集模型已被用户明确否定。09—18号历史实验可用于说明排错过程，**不能混入当前单格模型的性能结论**。

## 四、总体实验设计为什么这样安排

实验按问题逐层推进，而不是先固定一个混合算法，再挑有利场景。

### 层次1：模型和结果是否可信

目的：排除路线穿障碍、遗漏目标、删除遮挡任务、从错误位置起算等错误。

方法：生成事件前执行历史，冻结事件后输入；保存目标、已完成格、障碍、当前位置和基地；用独立路线审计检查每条移动、覆盖和返航。输入及源码归档并保存哈希。

这一层是后面比较的前提。通过只能证明符合当前抽象模型，不能证明真实飞行安全。

### 层次2：哪些候选机制真的减少代价

目的：区分旧路线修补、整体重算、条带约束、图树组织等思想的效果。

方法：先运行完整轻量原型，再冻结条带、访问解或执行规则做对照，避免多个模块一起改变后无法归因。

例如，拆分旧路径段时只放开固定条带上的服务约束；跳过途中已覆盖目标时固定条带、访问顺序和方向；增加横纵划分时检查实际路线，而不只比较条带数量。

### 层次3：基线还有多少真实优化空间

目的：避免把本来已经最优的简单图作为创新目标，也避免把某条长预算启发式路线误称为最优解。

方法：小图用两种独立精确表述——格级“位置＋剩余目标掩码”搜索与最短路距离上的Held–Karp访问排序——交叉核对全局最少步数；中等图保存最好已知合法路线并计算严格下界。

精确解是评价参照，规模指数增长，不是计划部署的主算法。中等图的上下界可能不紧，不能把上下界之差都写成可实现收益。

### 层次4：相同计算预算下，路线质量怎样变化

目的：判断“较少计算能否更早得到较短路线”，同时区分覆盖算法与实现效率。

方法：相同地图、历史、目标、保底候选与时限，对多个预算进行重复配对；完整记录无路线失败和合法超时候选。再单独做插桩定位，最后回到未插桩的实现对照。

相同墙钟时限有实用意义，但Python启发式与C++ GLNS的比较仍有语言、实现质量影响。不能把所有差距都解释成算法思想优劣。

## 五、现在实现了哪些算法，完成度如何

| 方法 | 当前已完成内容 | 能否称完整复现 |
|---|---|---|
| A* / BFS | 合法格上的最短连接路径或距离；独立路径核验 | 是基础连接工具，不是整条覆盖规划器 |
| P1旧路线修补 | 从旧任务顺序恢复剩余访问，插入新增目标并修复连接 | 自建工程基线，不对应某篇完整复现 |
| P2 / P2_SHARED | 横纵扫描、最近邻、2-opt，多候选实际展开并比较；SHARED另加共同保底候选 | 自建强基线，不是全局最优算法；不同版本结果须分别标注 |
| P3 / P4 | 区域分组、旧段复用的轻量原型 | 已实现原型，早期成绩多来自旧成像模型，不作为当前主要证据 |
| OARP-Replan适配 | 两类条带数学模型、整数结果检查、路径段/方向GTSP建模、真实GLNS求解及核心对照 | **核心适配实现，未完整复现原论文端到端流程** |
| STRIP_HV | 横纵最大条带候选＋GLNS排序＋共同保底＋途中覆盖处理 | 自建条带基线，不能直接命名为原版OARP |
| TREE_MST | 剩余目标度量图最小生成树、两个DFS访问序列、有限2-opt | 自建树候选，**不是TRACE，也不是C*** |
| 全局精确参照 | 两种独立精确表述及小规模核对 | 当前简化模型上的精确评价器 |
| P2_BFS | P2规则不变，批量缓存精确距离并保留A*路径选择 | 已验证的工程优化，不是论文创新 |
| TRACE | 已有全文精读、算法解释及核查笔记 | **未代码复现**；MST原型的成败不能代表TRACE |
| C* | 单独目录保存历史核心复现与实现约定、验证材料 | 本轮未重新运行或全面代码审核；不能当作已经完成当前单格场景等条件比较 |

OARP缺失的关键部分包括原论文完整遇障—背景计算—继续运动—新中断循环、原机器人运动时间模型与原实验平台/数据。当前64例的运行限制校准上限未实际生效，也不能宣称已验证原限时机制的现场价值。原始GLNS为Julia实现，本地使用C++移植版；并非作者完整代码栈。

## 六、当前有效实验批次与结果

### 数据规模与用途

| 数据组 | 独立冻结快照数 | 主要结构与用途 | 对应报告 |
|---|---:|---|---|
| 单格模型基础组 | 64 | 两种尺寸、开放/走廊域、早/晚进度、8类事件组合；恢复公平比较和机制诊断 | 20—24 |
| 中等规模组 | 24 | 两种新尺寸、不同历史方向/阶段、扩展和局部障碍；等预算和耗时诊断 | 25、28—29 |
| 小规模精确组 | 48 | 剩余目标1—12格；确认全局最优差距 | 26 |
| 结构压力组 | 96 | 宽度变化、拐弯、错位结构；剩余目标0—11格 | 27 |

四组共232个不同命名的冻结快照，是我们人工生成的开发数据，不是232次真实施工观测。其中部分共享同一初始执行历史，只改变事件；并非232个独立同分布样本。基础组被多轮反复使用，中等规模组被run20、23、24、25反复使用；不能把执行次数累加成独立地图数量。这些场景已参与选择，应视为开发集，未来需要另设测试集。

### 1. 重新建立单格公平基线

64例中P2全部有合法路线；P1有5例未在预算内得到合法路线。共同成功的59例里，P2短28例，P1短10例，21例相同。

意义：只修补旧路线并不自动更好；强基线需要完整保留。P1失败不能按0步算入平均值。

### 2. OARP核心适配与机制对照

- 两种核心版本共128条最终路线合法；有552个小规模条带核验组合及固定GTSP子问题精确检查。核心版本2总步数10188，P2为10144；核心版本2赢7例、平24例、输33例，尚无总体优势。
- 固定条带、拆开旧段约束：每种版本12/64例改善，52例相同。核心版本2结合保底后总步数10072；仍有不少场景输给P2。
- 固定访问结果、跳过途中已经完成的服务：每种版本37/64例缩短，27例相同；核心版本2结合保底后总步数9970。P2原本已有同类执行规则，因此这是公平执行修正，不能独占为创新。
- 增加横纵条带候选：结合已有候选后总步数9788，较P2的10144更低；但增加了搜索机会，没有等预算约束，不能据此宣称优于P2。

意义：旧段约束和服务执行方式确实会影响步数；“更少条带”未必对应更短实际路线。但这些局部改善还不足以组成稳定的新方法。

### 3. 新场景、相同5秒预算检验

24例全部方法均有合法路线：

| 方法 | 总步数 | 相对P2：赢 / 平 / 输 |
|---|---:|---:|
| P2_SHARED | 3384 | — |
| STRIP_HV | 3514 | 3 / 4 / 17 |
| TREE_MST | 3558 | 5 / 5 / 14 |

意义：旧数据上增加候选获得的改善没有稳定转移到这批新结构参数；图树候选也没有自然胜过全量重算。不能把“树结构看起来高级”当成优势证据。该24例后来继续用于诊断，现已不是未见测试集。

### 4. 两组全局最优参照

| 数据组 | 精确最优总步数 | P2总步数 | P2达到最优的例数 |
|---|---:|---:|---:|
| 48例小图 | 548 | 548 | 48/48 |
| 96例结构压力图 | 1464 | 1466 | 95/96 |

96例中有6例无剩余待检格，任务只需合法返航；排除这6例，P2为89/90最优。两种精确表述每例一致。唯一反例P2为23步、最优21步；不能把这个2步差距包装成普遍缺陷。

意义：当前小图已基本饱和，需要在更有代表性的中等规模上判断问题，而不是持续构造极小反例。

### 5. 中等规模预算敏感性

24例×3方法×5预算×2重复，共720次，均有合法完整路线。每个表格数为48次执行的总步数：

| 预算 | P2_SHARED | STRIP_HV | TREE_MST |
|---|---:|---:|---:|
| 0.1秒 | 7700 | 7276 | 7820 |
| 0.5秒 | 7398 | 7086 | 7670 |
| 2秒 | 6988 | 7002 | 7220 |
| 5秒 | 6768 | 7002 | 7116 |
| 20秒 | 6768 | 7002 | 7116 |

原P2在0.1秒下比自身20秒多932步，约13.8%；5秒与20秒相同。STRIP在0.1秒较强、充分预算却总体更差。这提示计算与路线质量存在权衡，但不是证明现实必须在0.1秒内反应。

按每个快照只计一次，全部方法中最好已知可行路线合计3336步，严格下界合计3128步；P2充分预算合计3384步。因此其总最优差距介于48与256步，只有2例已通过上下界一致证明最优，其余22例未知。不能声称中等图的最优解已经算出。

### 6. 本轮：先优化强基线，避免虚假算法优势

24例插桩审计显示开销主要落在最近邻和2-opt；原程序已有缓存，但仍有206,512次首次点对A*搜索和大量缓存查询。

另做384次不插桩配对，保持覆盖算法规则不变，只改为按起点BFS距离缓存：

- 20秒档实际计算总耗时47.238→17.648秒，降低约62.6%；路线逐点不变。
- 0.1秒档总步数7700→7424，减少约3.58%；0.5秒档7396→6944，减少约6.11%。
- 5秒、20秒共192条路线与旧20秒参考逐点相同；全部384条合法。
- 24条剖析路线及384条配对路线独立核验通过，6项回归测试通过。

意义：时间预算缺口部分是工程效率问题。新版还有短预算损失，但现在不能直接宣称需要一个创新混合算法。与STRIP的正式胜负需在统一基础设施下同批重测，不能跨批直接定论。

## 七、哪些结论可靠，哪些仍然缺证据

| 判断 | 确定程度 | 依据与边界 |
|---|---|---|
| 当前归档路线符合单格模型，统计可核查 | 高 | 独立审计、账本/哈希与精确参照核对；限于当前输入 |
| P2在当前微型开发集很强 | 高 | 两种精确表述支持48/48、95/96最优 |
| 原实现的部分短预算差距来自距离计算开销 | 高 | 同覆盖规则、充分预算路线一致、配对实现对照 |
| 目前简单条带/树候选没有稳定优势 | 高 | 对当前已测试场景和预算成立，不等于所有树/条带方法无价值 |
| 合理优化后仍值得研究限时结构复用 | 中 | 仍有短预算损失和已知可行改善，但其他常规优化可能解释它们 |
| 人工地图能代表施工现场事件分布 | 低 | 没有真实分布、频率与几何统计验证 |
| 当前方案已经有可发表的创新 | 低，尚未证实 | 主方法未确定，也没有独立测试上的稳定收益和完整相关工作排重 |

**不适合给“论文完成了百分之多少”。** 平台和诊断已有实物，但创新不是按代码行数或实验次数线性积累的；关键门槛还没有跨过。

## 八、还缺什么，接下来按什么顺序做

### 优先1：冻结合理优化的共同基线，做一轮有上限的新场景复核

将距离计算、实际路径、保底候选、统计规则统一，再同批比较P2、条带与树候选。新地图应扩展尺寸、非规则宽度、拐角/分支和障碍位置；生成规则提前固定，不能看成绩后挑选。旧图用来开发，新图最终评价前不反复调参。

目的：判断当前时间—质量差距是不是换图、修实现后仍存在。可先做小批量试运行检查可行性，再冻结正式批次；不需要立刻数千次求解或训练模型。

### 优先2：只对仍存在的缺口设计少量完整轻量候选

可能考虑“事件影响范围内更新、保留未受影响结构”和“按计算预算安排候选搜索顺序”，但它们只是待检验假设。需要明确输入、维护结构、更新操作、停止条件和保底策略；与优化后的全量重算相比，同时报告步数、实际计算时间和失败率。

必须区分：复用已完成格是所有方法都应遵守的任务规则；真正需要检验的机制是复用哪些规划结构、为何减少计算、是否牺牲全局路线质量。若常规优化已足够，不能强行给简单缓存或候选拼接起新算法名。

### 优先3：候选有稳定价值后，再做多事件闭环和最终对照

目前从真实历史出发，但不是完整持续执行。要验证“增量更新”的收益，最终需让无人机执行一段，再发布下一事件，以当时真实位置和覆盖状态重规划，累计总步数、重规划耗时和覆盖结果。事件只在发布时揭示，所有方法共享同一外生事件协议；不能让某算法因走到不同位置而无意获得未来信息优势。

多事件实验是论文主题的直接证据；视觉、飞控、实机不是当前必须搭建的前置系统。若以后加入电量或停机等待成本，需单独标定或做透明的参数敏感性，不把未经标定的步数直接叫真实能耗。

### 优先4：补足论文层面的严谨比较

最终应包括：简单覆盖/最近未覆盖对照、合理优化的整体重算、与主方法最匹配的文献适配基线，以及小图精确/中图上下界参照。不要求将所有文献复现一遍。TRACE是否值得实现，应由最终主机制是否涉及分解树决定；C*历史代码需要单格和同信息条件适配后才能比较。

需要消融验证贡献来源、足够的重复运行、独立测试和失败案例，明确适配差异；在确定主方法后再针对性核查新颖性，不能仅凭三篇论文没有同样写法就认定创新。

## 九、建议保留的研究决策

继续做算法研究，暂不扩展系统范围。保持“两类事件、一个剩余覆盖问题”。下一轮重点是优化后基线的跨结构复核；如果它仍然接近最优、短预算损失也很小，应接受目前机制空间不足，重新评估切入点，不能靠更弱基线、更紧但无依据的时限或选择性场景证明优势。

目前积累最有价值的是一个能够否定错误想法的实验环境。它已经阻止我们把模型偏差、额外搜索机会和实现低效当成算法创新。能否转化为论文，取决于下一阶段是否找到并解决一个稳定、可解释、与已有方法有区别的缺口。
