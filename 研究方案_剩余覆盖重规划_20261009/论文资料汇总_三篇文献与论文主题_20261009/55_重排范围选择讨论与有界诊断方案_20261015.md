# 重排范围选择：讨论与有界诊断方案

日期：2026-10-15。状态：讨论草案，尚未实现范围选择器、未执行本方案、未确认创新。三基线v2、PPCPP候选、历史输入和结果不变，留出地图不使用。

## 1. 用户已明确的目标与例子

用户确认主目标为：**同样计算预算下路线更短，计算时间合理。** 计算时间作为共同约束和单列指标，不把少算时间与多走路混成未经解释的加权分数。

讨论例子：当前位置前有A、B、C、D四个剩余覆盖区域。A前出现障碍，若重新规划AB后可以接回C的正常入口，CD及返航可继续原计划，就不必无条件重排全部区域。影响范围已接近全部剩余工作时，应考虑直接整体重算。

这是合理的候选方向，不是已经验证的算法结论。关键是区别“已经恢复可行”与“继续扩大范围是否有路线质量收益”。

## 2. 两种范围必须分开

- **可行性修复范围**：至少修改多少旧计划，才能覆盖全部当前可检任务、避开障碍并返航。
- **质量优化范围**：在同预算下，放开哪些额外旧约束值得，能否进一步减少整条实际路线的步数。

AB修复后能接C，只能证明可能恢复可行，不能证明ABC重排一定没有收益。反过来，扩大自由度也不保证有限时间启发式得到更短输出；必须保留已有合法候选，不用较差新候选覆盖它。

“重排范围”是允许改变哪些覆盖任务的组织/旧路线约束，**不是禁止无人机经过范围外自由格，也不是把寻路地图裁成局部窗口**。所有连接仍在完整当前公开自由地图中求合法路径。

## 3. 建议的第一版机制框架（待实现）

### 3.1 先确定必须处理的部分

障碍事件：检查旧剩余路线的所有实际移动格/边与返航段，标记碰撞、断开的覆盖段和失效连接。一个障碍若影响多处不相邻旧计划，必须全部登记，不能只修第一次相遇位置。

扩展事件：全部新增未检目标必须纳入任务。候选接入位置按当前地图合法距离与旧计划衔接关系考虑，不能只按欧氏距离选最近块。飞行域固定时，新增目标未必改变任何旧最短距离，因此不能仅用“旧连接距离变化”检测扩展影响。

两类事件均仅使用当前公开状态与已有旧计划。若使用事件前距离缓存，必须证明来自此前公开信息并统一计时；首版可不依赖该缓存。

### 3.2 用“接回原路线的接口”检查局部修复

AB重排后保留CD，应检查：

1. 当前位置到局部任务、局部内部和接回C入口的路径均合法。
2. 原CD实际路线以及D之后的返航段仍合法，不只检查C/D目标格。
3. 局部实际轨迹与保留部分合起来，完成全部当前未检目标；新增目标没有落在两边都不负责的空隙。
4. 暂缓账本正确，障碍下未检目标没有算完成。
5. 完整拼接路线满足资源上限并通过独立审计。

对固定接口，要优化的是`保留前缀 + 局部覆盖 + 接回后缀的连接 + 保留后缀及返航`的总步数，而不是局部覆盖段单独最短。如果接回位置改变，连接/后缀成本也必须同时变化。

接口检查可以给出明确可行性结论；它不是范围外没有优化收益的证书。

### 3.3 逐步扩大可改动的旧计划

从必须修改的块/段出发，比较加入相邻旧任务块或解除相邻旧连接约束的候选。候选包含不同接回位置；障碍影响不连续时允许多个修补段，不强制把其间大量无关任务都包入一个空间圆圈。

建议考察三类在线信号：

- **硬失效信号**：接回接口不合法、保留后缀仍碰撞、漏检或不能返航；需要扩大/更换接口，或报告整个状态不可行，而不是继续输出局部半成品。
- **边界机会信号**：扩大一层后的实际完整路线更短，或小规模边界交换发现降低跨区往返的机会；它是收益线索，不是全局最优证明。
- **规模与剩余时间信号**：可改目标数、覆盖块数、连接查询量、已消耗时间及剩余预算。块数不等于面积或优化复杂度，需同时记录。

不先拍定“扩大一层没改善就停”。启发式未改善可能因为搜索不足；相邻一层无收益也不排除再扩大后有组合收益。这正是诊断需要检验的误判。

## 4. 何时整体重算、何时停止

整体重算候选触发情形：

- 必须修改的部分已覆盖几乎全部剩余任务，局部复用收益可能消失；
- 多个失效连接散布全计划，拼接方案反复跨区；
- 为找到合法/有竞争力的接回接口，范围已不断扩大；
- 宽范围搜索预计比继续局部探测更划算，并且还剩足够时间。

“接近全部”的比例和时间估计尚未确定，不预设80%等数值作为已验证阈值。至少比较范围内未检目标占比、可改块占比与时间，不能只按块数定阈值。

所有探测、范围判断、保底、局部求解、最终可能的整体求解共用一个总截止时间；不得局部耗完后，再免费调用20秒P2。进入整体阶段也不保证一定算完；截至总预算前只返回已接受的完整合法候选。

没有合法接口时要区分局部限制导致失败与整个地图/资源不可行，后者不能通过“扩大范围”解决。

## 5. 怎样做第一轮实验——先诊断范围，再设计选择器

### 5.1 先测“哪些范围有用”，不直接训练/调阈值

从现有12个开发锚点出发，覆盖小中大、四几何层、六事件。补入相同原始历史、相同进度的无变化对照，最多24输入；按原状态标识/几何规则选择，不看方法输赢选图。两锚点本来无变化，去重后预计22输入，确切任务数须在运行前检查并落盘。

无变化对照用于判断：收益究竟与事件后新增的重排需要有关，还是旧原始扫描本来就容易被一般优化改进。不能据此声称已经完成算法因果分解。

范围对照建议为：必须修改的最小候选、向旧计划邻接扩一层、扩两层、全部放开。定义须嵌套并固定共同覆盖表示/求解器；重复范围去重并留账。具体块划分、断点与接回接口枚举仍须先写清并做小例子检查，不能留到看结果后更改。

另列完整冻结P2_MULTI作为强控制。全部放开若仍明显输P2，应先审查覆盖表示和求解器，不能把这类损失解释成范围判断错误，也不能回退弱P2。

初诊断建议预算1秒和20秒、一个固定配对种子、新进程，最多24×5种设置×2预算=240次；按预计22输入为220次。此为实验规模上限草案，不是已经启动的批次。单次运行不估计时间稳定性；后续选择器验证再另定重复。

各固定范围实验均独立享有相同总预算，测量范围约束的作用。其事后择优只作为开发诊断，**不是在线选择器的成绩，也不能免费供在线算法使用**。若实现自适应选择器，必须另跑一次总预算包含全部探测的端到端实验。

### 5.2 预定记录

合法输出/失败原因、完整含返航步数、范围目标/块占比、接口与跨区移动、连接/范围判断耗时、核心求解耗时、最终来源、软超时和原始路线；按基础地图汇总，不把同图状态算独立地图。

重点看：

1. 最小范围何时已接近该批全部放开/强P2，何时明显较差？
2. 扩大范围是否有可重复的收益，以及它消耗的预算是否反而损害同预算质量？
3. 哪些可在线取得的信号能识别需要扩大者，又不会将大量本可局部处理的状态误判为全局？
4. 无变化时也出现的收益占多大，是否只是一般路线优化而非事件范围机制？

“接近”的容许路程差须在诊断协议中预声明并同时报告原始差，不能结果出来后移动标准。选择规则若从这些开发结果产生，需要在另一组未参与规则选择的开发状态验证，仍不使用留出地图。

### 5.3 停止与否定条件

若固定小范围几乎从不在同预算下获得可竞争路线，或范围选择开销抵消收益，或全部放开表示本身明显弱于强P2，应停止当前选择器路线、定位原因，而非无限追加阈值。若只能靠事后知道哪种范围最短才能获益，也不能称在线选择已成立。

## 6. 与已做工作/邻近文献的边界

第22份已检查过解除旧路径段约束，第23份检查过途中覆盖后跳过服务，第41份检查过固定条带顺序/方向/返航。不能重复这些机制后宣称新发现。本轮新问题拟为“如何选择解除约束的范围及何时扩大”，不是单纯拆开全部条带。

[OARP-Replan，VI](https://arxiv.org/html/2311.17837v2#S6)已将未改变连续路径压缩为可双向访问的路径集合，再与新条带一起求GTSP；因此它不是简单把其余块全锁死的弱对照。

[TRACE，IV-C](https://arxiv.org/html/2609.21777v1#S4.SS3)保留未受影响区域相对顺序、对分裂子区域局部排序。这与“只改受影响部分”高度相关。

上述原文于本次讨论重新核对。仅“自适应范围/保留旧计划”不足以证明新颖性；新增目标适配、接口选择、范围扩大与质量判据都还需具体机制和针对性文献检索。本草案未确认这些点是首次提出。
