# 优化旧参考与局部搜索收益归因复核

日期：2026-10-16。第65份保存证据的事后诊断，不是新增性能实验。

## 1. 问题与做法

核查P2_REF下局部方法的优势是否只是共同保底更短。只使用LITERAL与同输入同预算P2的40组配对，不把与其外部段逐点相同的RECONNECT重复计为新样本。

从20输入离线重建共同保底F：按旧路线首次出现安排剩余目标，再追加未列目标，使用冻结规范的规范端点方向最短连接，并依实际附带覆盖跳过已完成点。另一份独立A*及覆盖账本与共享几何实现逐点交叉核对，20条全部合法；有记录的共同保底接受项长度逐条匹配。没有调用solve，没有新在线预算/性能成绩。

同参考内L为局部最终路线、P为整体P2最终路线，均不长于同一F；逐项验证：L−P=(F−P)−(F−L)。该恒等式是结果分解，不是随机化因果识别。

## 2. 完整分组结果

每组10个既有开发事件。步数改善为相对共同保底的总减少步数。

|参考|预算|共同保底总步数|局部总改善|整体P2总改善|局部改善保底的状态数|局部胜P2|胜例中局部也严格改善保底|
|---|---:|---:|---:|---:|---:|---:|---:|
|RAW|1秒|6311|442|220|7|1|1|
|RAW|20秒|6311|914|1116|10|1|1|
|P2_REF|1秒|6323|936|284|8|8|8|
|P2_REF|20秒|6323|1254|1128|9|6|6|

**P2_REF的共同保底并未在总量上更短：6323比RAW的6311多12步。** 跨参考的总量只是描述，不能当单变量因果结论；但同参考配对足以排除“局部胜例只是返回共同全局保底”的解释：1秒8个胜例、20秒6个胜例全部严格改善同输入共同保底，整体P2也已不长于该保底。

## 3. 不把初始化收益全部算成后续搜索收益

所有40次LITERAL的第一条合法核心候选都来自scope_core:common_fallback：这是窗口内部的修复初始化，拼接窗口外段后形成完整核心路线，不是共同全局保底F。

|参考|预算|第一条核心已短于最终P2的状态数|第一条核心到最佳核心累计缩短|
|---|---:|---:|---:|
|RAW|1秒|1|212步|
|RAW|20秒|0|702步|
|P2_REF|1秒|3|176步|
|P2_REF|20秒|1|494步|

因此P2_REF的1秒8个胜例中，只有3例在首条局部修复候选时已胜最终P2，另外5例是在后续局部候选构造/搜索中才获得胜出路线。不能将这5例进一步全归2-opt：后续流程还包含扫描、最近邻及多初始候选，当前仅定位到阶段，不隔离某个算子。20秒首条核心有1例胜最终P2，最终共6例胜，含5例后续获得的胜例。

首条到最佳核心的改善不是最终相对保底改善，两者分母不同、可能存在保底更短，不相加宣传收益。

## 4. 当前判断及下一步门槛

1. 局部修复/搜索确实在这些固定开发事件中产生了超出共同全局保底的合法改善；不能再简单解释为旧参考保底占便宜。
2. 外部重连不是收益来源（第65份逐点相同）；目前仍不能证明范围规则最优、接口最合适或局部策略普遍领先。
3. P2_REF的额外准备成本仍另计；旧参考是在固定检查点替换的尾段，不是从强初始计划真实执行到检查点的完整历史。10地图、一个种子、事后分析不支持稳定性/显著性结论。
4. 暂不释放更多接口、不调圈层。下一项建议先写连续执行验证协议：只在事件前公开地图规划共同初始路线，沿该路线真实更新覆盖账本到预定进度，再公开既定事件；所有比较方法共享同一个实际当前位置、历史和未执行尾段。将事件前计划费用单列，事件后统一预算。这样验证收益是否在自洽历史中保留，而不是继续优化人为尾段替换。
5. 上述连续执行验证尚未实现/冻结/运行。它最多是现有固定局部策略的真实性与可行性检查，不自动构成主算法或创新；若信号消失，应回到正式基线与短板整理，不继续无限细分。留出继续不用。
